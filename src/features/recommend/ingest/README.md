# ingest/ — 크롤러 출력 어댑터

> 작성자: 박재우 · 작성일: 2026-09-03

**크롤러 출력 형태가 우리 스키마에 직접 닿지 않게 하는 층.**

크롤 데이터는 09-02 에 도착·적재됐다 (레시피 46,353건 · 후기 624,422건).
원본 `raw_data/recipe_raw_data.jsonl` 은 209MB 이고 후기 작성자 닉네임이
평문으로 들어 있어 **저장소에 올리지 않는다** — 받는 곳은 `raw_data/00_README.md`.
어댑터 층은 다음 소스로 갈아탈 때를 위해 남긴다.
어댑터를 두면 **실제 JSON 이 왔을 때 YAML 하나만 고치면 되고**,
`adapter.py` · DB 스키마 · 정규화 파이프라인은 건드리지 않는다.

```
크롤러 출력 (형태 미상)
        │
        ▼
  sources/mangae.yaml     ← 실제 JSON 을 보고 여기만 고친다
        │
   adapter.py             ← 건드리지 않는다
        │
        ▼
  recipe · recipe_ingredient_raw · recipe_step
```

## 실제 크롤링 데이터가 오면

```bash
# 1. 진단 — 무엇이 맞고 틀린지 리포트
make probe SAMPLE=경로/샘플.json

# 2. sources/mangae.yaml 의 paths 를 실제 키에 맞게 수정

# 3. 다시 진단해서 ✅ 가 나올 때까지 반복
```

## probe 가 알려주는 것

| 항목 | 의미 |
|---|---|
| **매핑 성공** | 어느 경로에서 잡혔는지 + 실제 값 샘플 |
| **재료 그룹명 보유율** | `[재료]/[양념]/[고명]`. role 판별의 1차 근거 |
| **누락 · 폴백** | 🔴 치명 / 🟡 품질 하락 / ⚪ 무시 가능 + **없으면 무엇이 나빠지는지** |
| **raw_json 원본 보존** | 최상위 키 목록 |

`IMPACT` 테이블의 문장은 **크롤링 담당자에게 그대로 전달**할 수 있게 썼다.
"이 필드 주세요"가 아니라 "이게 없으면 무엇이 나빠집니다"로 말하기 위해서다.

## 심각도 기준

| | 예 | 의미 |
|---|---|---|
| 🔴 | `source_id` `title` `ingredients` | **적재 불가.** 없으면 레시피가 들어가지 않는다 |
| 🟡 | `group_name` `cook_minutes` `view_count` `dish_type` | 적재는 되나 **추천 품질이 떨어진다** |
| ⚪ | `url` `description` `servings` `difficulty` | 무시 가능. 현재 설계에서 비중이 낮다 |

## 🔴 `raw_json` 은 원본 전체를 담는다

파싱한 필드만이 아니라 **크롤러가 받은 것을 통째로** 넣는다.

> **파싱은 나중에 해도 되지만 수집은 미룰 수 없다.**
> `raw_json` 에 원본이 있으면 분류 4축이든 뭐든 언제든 재파싱할 수 있고,
> 없으면 재크롤링이다 (설계 2-3-1).

## 폴백 정책

| 폴백 | 동작 |
|---|---|
| `null` | NULL 로 둔다. **0 이나 빈 문자열로 채우지 않는다** |
| `const:<v>` | 고정값 (`view_count → 0`) |
| `derive:<fn>` | `adapter.py` 의 파생 함수 |

### 🔴 `cook_minutes` 는 반드시 NULL

파싱 실패를 `0` 으로 채우면 **모든 실패 레시피가 "가장 빠른 요리"로 최상위에 올라온다**
(설계 2-3). 랭킹에서는 NULL 을 중립값 `0.5` 로 처리한다 (설계 5-2-1 D군).

### `group_name` 이 없으면 — `derive:group_from_flat`

role 판별이 `is_staple` / `is_seasoning` 플래그와 수량 표현(`약간` `조금`)으로만 이뤄진다.
시드에 `is_seasoning=true` 가 110종 있으므로 양념은 상당 부분 잡히지만,
**고명 판별이 어려워져 `essential` 과다 판정 → 추천 후보가 좁아지는 방향으로 실패**한다.

치명적이지는 않다. **다만 나중에 수집하려면 재크롤링이므로 지금 받는 것이 훨씬 싸다.**

## 파일

```
ingest/
├── sources/
│   ├── _spec.yaml       매핑 스펙 정의 (문서)
│   └── mangae.yaml      만개의레시피 매핑 — 실크롤 46,552건으로 확정 (09-02)
├── adapter.py           YAML 매핑 → 우리 스키마. 건드리지 않는다
├── probe.py             샘플 진단
├── fixtures/            테스트용 합성 크롤링 출력 3종
│   └── real/            실크롤 구조 3건 — 🔴 후기·설명은 더미로 교체했다
│                        (닉네임·후기 원문을 저장소에 두지 않는다)
│   ├── best_case.json     그룹명 · 분류 4축 전부 있음
│   ├── no_group.json      그룹명 없음 · 키 이름 다름
│   └── minimal.json       필드 3개뿐
└── 00_README.md
```

## 새 소스를 추가하려면

`sources/<name>.yaml` 을 만들고 `--source <name>` 으로 지정한다.
Food.com 공개 데이터로 전환하는 경우(실행계획 W3 컷라인)에도 같은 방식이다.
