# aiServer 환경변수 목록

**정하는 것**: 이 서비스가 읽는 환경변수 전부 — 이름, 기본값, 비밀 여부, 뜻 — 와 그중 백엔드·DB 구성 논의 뒤에 값이나 존재가 바뀌는 것

**적용 대상**: 배포 설정을 쓰는 클라우드 팀, 값을 발급하는 백엔드·데이터 파트. 정본은 `src/config.py` 의 `Settings` 이고 이 문서는 그것을 표로 옮긴 것입니다

**버전**: 1.0.1 · **최종 수정**: 2026-09-18 · **작성자**: 유재현

---

## 1. 읽는 법

- 이름과 기본값은 **코드가 정합니다.** `src/config.py` 의 필드가 그대로 대문자 환경변수입니다(`db_host` → `DB_HOST`). 여기 적힌 값이 코드와 어긋나면 코드가 이깁니다.
- "이미지 기본값" 은 루트 `Dockerfile` 이 `ENV` 로 굽는 값입니다. 코드 기본값과 다른 것은 두 칸을 다 적었습니다.
- 값이 비어 있는 채로 넘기면(`KEY=`) 숫자 필드가 빈 문자열을 받아 기동이 실패합니다. 쓰지 않는 변수는 넘기지 않습니다.
- 4절은 아직 정하지 못한 것입니다. 백엔드·DB 구성 방식이 정해지면 그 절을 지우고 2절·3절을 고칩니다.

## 2. 필수 (없으면 기동 시점에 중단)

| 이름 | 기본값 | 비밀 | 설명 |
|---|---|---|---|
| `DB_HOST` | | | PostgreSQL 주소. 통합 전에는 AWS RDS 엔드포인트(`container_handover.md` 12절) |
| `DB_NAME` | | | 데이터베이스 이름. 로컬 compose 는 `recodb` 를 `POSTGRES_DB` 로 만들고, 초기화 SQL 은 만들지 않습니다 — RDS 에서는 `01_extensions.sql` 을 돌리기 전에 그 이름으로 만들어야 합니다(그 파일이 `ALTER DATABASE recodb` 를 부릅니다) |
| `DB_USER` | | | 접속 계정. 역할 분리의 뜻대로면 앱은 `reco_app` 입니다(`deploy/init/05_roles.sql`) |
| `DB_PASSWORD` | | 예 | 접속 비밀번호 |
| `INTERNAL_API_KEY` | | 예 | 내부 서비스 인증 키. 헬스체크의 `live` · `ready` 를 뺀 모든 경로가 `X-Internal-Api-Key` 헤더로 검사합니다. **외부 발급이 아니라 우리가 정하는 임의의 문자열**입니다 — 클라우드가 만들어 이 서버와 백엔드(`AI_INTERNAL_API_KEY`)에 같은 값을 주면 됩니다. 코드는 값의 형식을 보지 않고 일치만 봅니다(`src/deps.py`) |
| `GEMINI_API_KEY` | | 예 | 영수증 후처리 LLM(Google Gemini) 키. **Google 이 발급하는 값**이라 임의 문자열은 안 되고, 팀 소유 Google 계정·프로젝트에서 발급해 과금과 한도를 그 프로젝트가 지게 하는 것을 권합니다. 개인 개발용 키는 배포에 넘기지 않습니다. 없으면 기동이 멈추고, 있어도 아웃바운드 HTTPS 가 막히면 영수증 요청만 실패합니다 |

## 3. 선택 (기본값 있음)

### 3.1 컨테이너에서 만질 법한 것

| 이름 | 코드 기본값 | 이미지 기본값 | 설명 |
|---|---|---|---|
| `DB_PORT` | 5432 | | DB 포트 |
| `DB_SCHEMA` | reco | | 이 서비스의 테이블이 사는 스키마. 커넥션마다 `search_path` 로 걸립니다. 공유 DB 면 여기서 갈라집니다 |
| `LOG_LEVEL` | INFO | | 로그 레벨 |
| `OCR_WORKERS` | 3 | **1** | OCR 워커 프로세스 수. 컨테이너 실측은 워커 1 에서 유휴 456MiB · 영수증 1건 처리 중 536MiB 입니다. 코드 주석은 워커당 약 2.5GB 라 적고 있고 이 값은 부하 상황에서 재지 않았으므로, 올리기 전에 노드에서 직접 재십시오 |
| `PG_MAX_CONN` | 10 | | 커넥션 풀 상한. 레플리카 수 × 이 값이 DB 의 `max_connections` 아래여야 합니다 |
| `PG_MIN_CONN` | (= `PG_MAX_CONN`) | | 풀 하한. 비우면 상한과 같게 둡니다 — 작게 두면 반납 때 초과분을 닫아 매 요청이 새 커넥션을 엽니다(실측 p50 32ms 대 2.5ms) |
| `POOL_TIMEOUT_SEC` | 30 | | 풀에서 커넥션을 기다리는 상한(초) |
| `TZ` | (OS) | **Asia/Seoul** | 컨테이너 시간대. 앱 코드가 읽는 값이 아니라 OS 설정이며, DB 쪽 시간대는 별도로 `ALTER DATABASE ... SET timezone` 이 정합니다(`container_handover.md` 12절). 둘 중 하나만 한국이면 소비기한 임박 판정이 하루 어긋납니다 |

### 3.2 영수증 처리 튜닝값 — 실측으로 정한 값이라 배포에서 바꾸지 않습니다

| 이름 | 코드 기본값 | 설명 |
|---|---|---|
| `MAX_UPLOAD_BYTES` | 10485760 | 업로드 상한(10MB). 프론트·백엔드가 앞단에서 거르지만 서버도 같은 값을 둡니다 |
| `MAX_RECEIPT_ID_LENGTH` | 64 | 영수증 id 길이 상한(ULID 26자에 여유) |
| `OCR_MAX_PIXELS` | 1500000 | 총 화소가 이 값을 넘으면 비율을 유지한 채 줄여 인식 |
| `OCR_CLAHE_CLIP_LIMIT` | 2.0 | 국소 대비 보정 강도 |
| `OCR_CLAHE_TILE_GRID` | 8 | 국소 대비 보정 타일 수 |
| `OCR_SAME_LINE_HEIGHT_RATIO` | 0.6 | 같은 줄 판정 기준(글자 높이의 배수) |
| `OCR_WARMUP_HOLD_SEC` | 0.3 | 기동 예열 때 워커 하나가 작업을 붙잡는 시간. 0 이면 워커 하나가 예열을 전부 가져가 나머지가 뜨지 않습니다 |
| `GEMINI_MODEL` | gemini-3.5-flash-lite | 후처리 LLM 모델명 |
| `LLM_TIMEOUT_SEC` | 10 | LLM 요청 타임아웃(초). Gemini 가 10초 미만을 거부하므로 10 이 하한입니다. 백엔드 타임아웃 30초 = OCR 최악 10 + LLM 최악 11 + 여유 |
| `LLM_MAX_RETRIES` | 1 | LLM 재시도 횟수 |
| `LLM_BACKOFF_BASE_SEC` | 0.5 | 재시도 간격의 밑값(초) |
| `RECEIPT_PROMPT_VERSION` | 5 | 후처리 프롬프트 판. 출력 스키마는 판이 달라도 같습니다 |

### 3.3 추천 서빙·배치 값 — 추적 로그와 짝이 있어 배포에서 바꾸지 않습니다

| 이름 | 코드 기본값 | 설명 |
|---|---|---|
| `CANDIDATE_LIMIT` | 500 | 후보 조회 상한. `deploy/init/04_functions.sql` 의 `p_limit` 과 같은 뜻 |
| `EXPLORE_POOL_SIZE` | 200 | 탐색 풀 크기. 추적 로그의 `explore_pool_size` 와 같아야 합니다 |
| `PROPENSITY_MC` | 200 | 노출 확률 추정의 몬테카를로 반복 수 |
| `INGEST_BATCH` | 2000 | 적재 배치 크기(데이터 파트 배치만 사용) |
| `REVIEW_SALT` | (없음) | **비밀.** 후기 작성자 해시의 소금으로 예약된 값. 2026-09-18 기준 `config.py` 에 정의만 있고 읽는 코드가 없어 서비스 컨테이너에는 필요 없습니다. 쓰기 시작하면 한 번 정한 뒤 바꿀 수 없습니다 — 바꾸면 이미 적재된 후기의 해시와 어긋납니다 |

## 4. 아직 정하지 못한 것 — 백엔드·DB 구성 논의 뒤에 확정

이름과 기본값은 위 표대로 지금 확정입니다. 아래는 **값** 이 아직 없거나, 연동 방식에 따라 **변수가 새로 생기거나 없어지는** 것입니다. 각 줄의 "언제" 가 채워지면 이 절에서 지우고 2절·3절을 고칩니다. 백엔드에 보낸 질문은 `backend_schema_request.md` 에 있습니다.

| 무엇 | 지금 상태 | 언제 정해지는가 | 정해지면 할 일 |
|---|---|---|---|
| `DB_HOST` · `DB_NAME` · `DB_USER` · `DB_PASSWORD` 의 값 | RDS 인스턴스 미생성. `DB_USER` 를 `reco_app` 으로 줄지, 역할 3종을 누가 만들지 미정 | 클라우드가 RDS 를 만들고 초기화 SQL 을 적용한 뒤(G-32) | 2절의 설명을 실제 엔드포인트 규칙으로. 값은 문서에 적지 않고 시크릿 저장소에만 |
| 백엔드 연동 방식에 따른 새 변수 | 연동 방식 셋(DB 직접 읽기 · API 호출 · 동기화) 중 미정 | 백엔드 스키마 회신 | API 호출이면 `BACKEND_BASE_URL` · `BACKEND_API_KEY`(비밀) · 타임아웃이 생기고, 동기화면 소스 DSN 과 주기가 생깁니다. DB 직접 읽기면 새 변수가 없습니다 |
| 추천 로그를 어느 DB 에 남기는가 | 지금은 같은 DB 의 `recommendation_log`. 백엔드 DB 와 분리할지 미정 | 백엔드 회신 | 분리하면 `LOG_DB_*` 네 개가 생깁니다. 같은 DB 면 변경 없음 |
| `DB_SCHEMA` 를 바꿀 일이 있는가 | 전용 DB 라 `reco` 그대로 | 백엔드 DB 와 한 인스턴스를 나눠 쓰기로 하면 | 스키마 이름과 역할의 `search_path` 를 함께 정합니다 |
| `PG_MAX_CONN` 과 레플리카 수 | RDS 인스턴스 크기 미정이라 `max_connections` 를 모릅니다 | 클라우드가 인스턴스 크기를 공유하면 | 레플리카 수 × `PG_MAX_CONN` + 배치 접속 ≤ `max_connections` 이 되게 값을 정합니다 |
| `OCR_WORKERS` 의 메모리 상한 | 유휴 456MiB 실측과 코드 주석 2.5GB 가 다릅니다 | 부하 테스트 뒤 | 3.1 의 설명을 실측 하나로 고치고 메모리 요청·상한을 정합니다 |
| `INTERNAL_API_KEY` 의 회전 | 발급 주체는 클라우드로 정리(2026-09-18, 임의 문자열을 만들어 이 서버와 백엔드에 같은 값). 회전 절차 미정 | 백엔드와 합의 | 두 키를 동시에 받는 기간을 둘지 결정. 지금 코드는 키 하나만 검사하므로 회전은 두 서비스를 같은 배포에서 바꿔야 합니다 |
| `.env.example` 갱신 | `DB_SCHEMA` · `PG_*` 3종 · `CANDIDATE_LIMIT` · `EXPLORE_POOL_SIZE` · `PROPENSITY_MC` · `INGEST_BATCH` · `REVIEW_SALT` 9개가 빠져 있습니다 | 데이터 파트·`main` 소유 파일이라 알린 뒤 | 01의 1절 규칙("새 환경변수는 같은 커밋에서 갱신")대로 맞춥니다 |

## 5. 비밀값 주입

비밀값은 `DB_PASSWORD` · `INTERNAL_API_KEY` · `GEMINI_API_KEY` 셋입니다. `REVIEW_SALT` 는 쓰기 시작하는 시점에 넷째가 됩니다. 이미지에 굽지 않고 시크릿 저장소에서 주입합니다. `.dockerignore` 가 `.env` 를 빌드 컨텍스트에서 막고 있으며, 빌드한 이미지 안에 `.env` 가 없는 것을 확인했습니다(`container_handover.md` 8절).
