# aiServer 컨테이너 인수인계

**정하는 것**: 이 저장소를 이미지로 만들어 배포할 때 필요한 것 — 빌드 방법, 런타임 계약(포트·환경변수·헬스체크), 외부 의존, 실측 자원, 확인한 것과 확인하지 못한 것

**적용 대상**: 이미지 빌드·경량화·보안 스캔과 배포를 맡는 클라우드 팀. 이 저장소를 처음 여는 분을 기준으로 씁니다

**버전**: 1.0.0 · **최종 수정**: 2026-09-16 · **작성자**: 유재현

---

## 1. 무엇을 드리는가

이 저장소는 **서비스 하나**입니다. FastAPI 앱 한 개가 영수증 OCR 과 추천을 함께 서빙하므로 이미지도 하나입니다.

| 파일 | 위치 | 내용 |
|---|---|---|
| `Dockerfile` | 저장소 루트 | 4단계 빌드(base · builder · models · runtime) |
| `.dockerignore` | 저장소 루트 | 빌드 컨텍스트에서 비밀값·데이터·가상환경을 제외 |
| `docker-compose.yml` 의 `reco-api` | `deploy/` | 로컬에서 DB 와 함께 띄우는 용도. 배포용이 아닙니다 |

---

## 2. 빌드와 실행

**빌드 컨텍스트는 저장소 루트입니다.** 하위 폴더에서 빌드하면 `pyproject.toml` 과 `uv.lock` 을 찾지 못합니다.

```bash
docker build -t reco-ai-server:<tag> .
docker run --rm -p 8000:8000 \
  -e DB_HOST=... -e DB_NAME=... -e DB_USER=... -e DB_PASSWORD=... \
  -e INTERNAL_API_KEY=... -e GEMINI_API_KEY=... \
  reco-ai-server:<tag>
```

빌드 인자는 없습니다. 프록시나 사설 레지스트리가 필요하면 알려 주시면 넣겠습니다.

---

## 3. 요청 문서의 예시와 다른 점 셋

예시(`python:3.11-slim` + `requirements.txt`)를 그대로 쓰면 빌드가 되지 않거나 조용히 틀립니다.

| 항목 | 예시 | 이 저장소 | 이유 |
|---|---|---|---|
| 파이썬 | 3.11 | **3.12** | `pyproject.toml` 이 `>=3.12,<3.13` 이라 3.11 에서는 설치가 거부됩니다 |
| 의존성 | `requirements.txt` + `pip` | **`uv.lock`** + `uv sync --frozen --no-dev` | 이 저장소에 `requirements.txt` 가 없습니다. 잠금 파일이 정본이고 개발·CI·운영이 같은 버전을 쓰는 근거입니다 |
| 실행 대상 | `main:app` | **`main:create_app` (팩토리)** | 앱 객체가 아니라 앱을 만드는 함수입니다. 소스 루트가 `src/` 라 패키지를 설치해야 이 이름이 보입니다 |

`requirements.txt` 가 필요하시면 잠금 파일에서 뽑아 드릴 수 있습니다. 다만 그것을 빌드에 쓰면 두 벌이 되어 갈라지므로 권하지 않습니다.

## 4. 이미지 구성

```text
base     python:3.12-slim + 시스템 라이브러리 4종(libgl1 libglib2.0-0 libgomp1 tzdata)
builder  uv 로 의존성 설치 → 앱 설치
models   OCR 모델 가중치 내려받기 (약 98MB)
runtime  base + 실행에 필요한 것만 복사. 비 root 로 실행
```

**시스템 라이브러리를 base 한 곳에만 적은 것이 중요합니다.** 빌드 단계와 실행 단계에 따로 적으면 한쪽에만 있는 라이브러리가 생기고, 그러면 **빌드는 성공한 뒤 첫 요청에서** 터집니다. 실제로 만들다가 한 번 걸렸습니다.

- `libgl1` · `libglib2.0-0` — OpenCV(`import cv2`)
- `libgomp1` — Paddle 의 OpenMP 런타임
- `tzdata` — 없으면 `TZ` 를 줘도 조용히 UTC 로 돕니다

**OCR 모델은 빌드 때 구워 넣습니다.** 런타임에 받게 두면 컨테이너가 뜰 때마다 약 98MB 를 내려받고, 외부 통신이 막힌 환경에서는 준비 상태가 영영 되지 않는데 에러는 나지 않습니다. 구워 두면 같은 태그가 어디서 뜨든 같은 모델을 씁니다. 모델은 `/home/app/.paddlex` 에 있습니다.

### 4.1 크기

빌드 실측 **2.62GB** (linux/amd64). 큰 것부터입니다.

| 항목 | 크기 |
|---|---|
| paddle (딥러닝 런타임) | 719MB |
| opencv (`cv2` + `.libs`) | 182MB |
| pandas | 75MB |
| modelscope | 65MB |
| numpy | 43MB |
| OCR 모델 가중치 | 98MB |
| 가상환경 전체 | 1.5GB |

경량화 여지는 paddle 과 opencv 에 몰려 있습니다. 둘 다 영수증 OCR 에만 쓰이므로, 추천 API 만 필요한 배포라면 OCR 의존성을 뺀 별도 이미지를 만드는 쪽이 멀티스테이지 조정보다 효과가 큽니다. 필요하시면 만들어 드리겠습니다.

## 5. 런타임 계약

| 항목 | 값 |
|---|---|
| 포트 | 8000 |
| 실행 | `uvicorn main:create_app --factory --host 0.0.0.0 --port 8000 --workers 1` |
| 사용자 | 비 root (`uid 10001`, 이름 `app`) |
| 작업 디렉터리 | `/app` |
| 시간대 | `Asia/Seoul` |
| 쓰기 필요 경로 | 없습니다. 읽기 전용 파일시스템으로 띄워도 됩니다(`/tmp` 만 열어 주십시오) |
| 종료 | `SIGTERM` 에 OCR 워커 풀을 정리합니다. 유예 30초면 넉넉합니다 |

**워커는 1 로 두십시오.** 앱이 프로세스 안에서 OCR 프로세스 풀을 따로 띄우므로 uvicorn 워커를 늘리면 그 풀이 워커 수만큼 생겨 메모리가 배로 듭니다. 수평 확장은 레플리카로 해 주십시오.

### 5.1 환경변수

**필수 6개.** 없으면 기동 시점에 멈춥니다. 비밀값은 이미지에 굽지 않으며 `.dockerignore` 가 `.env` 를 빌드 컨텍스트에서 막고 있습니다.

| 이름 | 비밀 | 설명 |
|---|---|---|
| `DB_HOST` | | PostgreSQL 주소 |
| `DB_NAME` | | 데이터베이스 이름 |
| `DB_USER` | | 접속 계정 |
| `DB_PASSWORD` | 예 | 접속 비밀번호 |
| `INTERNAL_API_KEY` | 예 | 백엔드만 호출하도록 막는 내부 키. 모든 업무 경로가 `X-Internal-Api-Key` 헤더로 검사합니다 |
| `GEMINI_API_KEY` | 예 | 영수증 후처리 LLM 키 |

선택값은 기본값이 있습니다. 컨테이너에서 자주 쓰는 것만 적습니다. 전체 목록은 저장소의 `.env.example` 입니다.

| 이름 | 기본값 | 설명 |
|---|---|---|
| `DB_PORT` | 5432 | |
| `LOG_LEVEL` | INFO | |
| `OCR_WORKERS` | **1** (이미지 기본값) | OCR 워커 수. 메모리를 넉넉히 준 노드에서만 올리십시오 |
| `TZ` | Asia/Seoul | 바꾸면 소비기한 임박 판정 날짜가 달라집니다 |

## 6. 헬스체크와 프로브

| 경로 | 인증 | 뜻 |
|---|---|---|
| `GET /health/live` | 불필요 | 프로세스가 살아 있습니다. 무거운 자원을 건드리지 않습니다 |
| `GET /health/ready` | 불필요 | OCR 모델 적재가 끝났습니다. 그전에는 503 입니다 |
| `GET /health` | 필요 | 모델 버전과 DB 접속 여부를 함께 돌려줍니다. 운영 프로브용이 아닙니다 |

이미지 안에 `HEALTHCHECK` 로 `/health/live` 가 걸려 있습니다. 쿠버네티스에서는 아래처럼 나눠 주십시오.

```yaml
livenessProbe:
  httpGet: { path: /health/live, port: 8000 }
  periodSeconds: 10
readinessProbe:
  httpGet: { path: /health/ready, port: 8000 }
  periodSeconds: 5
startupProbe:
  httpGet: { path: /health/live, port: 8000 }
  failureThreshold: 12        # 모델 적재까지 실측 8~14초
  periodSeconds: 5
```

**liveness 에 `/health/ready` 를 쓰지 마십시오.** 모델을 올리는 동안 컨테이너가 죽고 다시 뜨기를 반복합니다.

`/health` 응답의 `redis` 필드는 **근거 없는 값입니다.** 지금 이 앱에는 redis 클라이언트가 없고 의존성에도 없습니다. 항상 참으로 나가므로 모니터링 신호로 쓰지 마십시오. 저장소에도 고칠 항목으로 적혀 있습니다.

## 7. 외부 의존

| 대상 | 필수 | 내용 |
|---|---|---|
| PostgreSQL 16 | 예 | 확장 네 개가 필요합니다 — `vector` · `intarray` · `pg_trgm` · `ltree`. 스키마는 `reco` 입니다. 로컬 기준 이미지는 `pgvector/pgvector:pg16` 이고 초기화 SQL 은 `deploy/init/` 에 있습니다 |
| Gemini API | 예(영수증 기능) | 아웃바운드 HTTPS 가 필요합니다. 막히면 기동은 되고 영수증 요청만 실패합니다 |
| Redis | 아니요 | 앱이 쓰지 않습니다(6절) |
| 모델 저장소 | 아니요 | 가중치를 이미지에 구워 두어 런타임 다운로드가 없습니다 |

컨테이너 안에서 DB 주소는 `localhost` 가 아닙니다. 서비스 이름이나 실제 엔드포인트를 `DB_HOST` 로 주십시오.

## 8. 실측치

호스트에서 이미지를 만들어 컨테이너로 띄운 결과입니다. 판정은 전부 종료 코드와 응답 코드로 했습니다.

| 항목 | 값 |
|---|---|
| 빌드 | 종료 코드 0 · 이미지 2.62GB |
| 기동 → `/health/live` 200 | 즉시 |
| 기동 → `/health/ready` 200 | 8~14초 (모델 적재 포함) |
| 유휴 메모리 | 456MiB (`OCR_WORKERS=1`) |
| 영수증 1건 처리 중 메모리 | 536MiB |
| 내부 키 없이 호출 | 401 |
| 내부 키로 `/health` | 200 · `db: true` |
| 추천 호출 `/v1/recommend` | 200 |
| 실행 사용자 | `uid 10001` |
| 시간대 | KST |
| 이미지 안 `.env` | 없음 |

메모리 요청은 **512Mi**, 상한은 **1Gi** 를 시작점으로 권합니다(`OCR_WORKERS=1` 기준). 워커를 올리면 워커 하나당 수백 MiB 를 더 잡으십시오.

## 9. 확인하지 못한 것

정직하게 적습니다. 아래는 저희 쪽에서 재지 않았습니다.

- **arm64(Graviton)** — linux/amd64 로만 빌드하고 확인했습니다. 멀티아키가 필요하면 알려 주십시오. Paddle 휠이 arm64 에 있는지부터 확인해야 합니다.
- **GPU** — CPU 전용 구성입니다. GPU 런타임은 베이스 이미지와 Paddle 패키지가 모두 달라집니다.
- **부하와 지연시간** — 단건 호출만 확인했습니다. 동시 처리량과 p95 는 재지 않았습니다.
- **쿠버네티스 매니페스트** — 6절의 프로브 예시는 참고용이고 실제로 적용해 보지 않았습니다.

## 10. 지금 알고 계셔야 하는 결함

**영수증 OCR 요청(`POST /v1/ocr/receipt`)이 500 을 냅니다.** 이미지 문제가 아니라 저장소가 현재 쓰는 라이브러리 조합의 문제이고, 컨테이너 밖 개발 환경에서도 똑같이 재현됩니다.

- 증상: 모델 적재와 헬스체크는 정상(`ready` 200). 실제 인식 요청에서 `NotImplementedError: ConvertPirAttribute2RuntimeAttribute not support` 로 실패합니다.
- 원인: PaddleOCR 이 기본으로 켜는 oneDNN 백엔드와 Paddle 3.3.1 의 실행기가 충돌합니다.
- 확인한 처방: 엔진을 만들 때 oneDNN 을 끄면 정상 인식됩니다(같은 이미지에서 7건 인식). 적용 여부는 영수증 기능 담당이 정합니다.
- **클라우드 팀이 하실 일은 없습니다.** 다만 CI 의 스모크 테스트에 이 경로를 넣으시면 지금은 실패하므로, 고쳐질 때까지 제외하거나 실패를 예상값으로 두십시오. 추천 경로와 헬스체크는 정상입니다.

## 11. 이미지를 손보실 때 부탁드릴 것

- `/home/app/.paddlex` 를 지우지 마십시오. OCR 모델 가중치이고, 지우면 런타임에 다시 받으려 합니다.
- 시스템 라이브러리 네 개(`libgl1` · `libglib2.0-0` · `libgomp1` · `tzdata`)를 빼지 마십시오. 넷 다 빼도 **빌드는 성공하고 실행 중에** 터집니다.
- `uv sync --frozen` 의 `--frozen` 을 빼지 마십시오. 잠금 파일을 무시하고 최신 버전을 끌어오면 개발 환경과 배포 이미지가 갈라집니다.
- 비밀값을 `ARG` 나 `ENV` 로 굽지 마십시오. 이미지 레이어에 들어간 값은 저장소에 올라간 뒤 지울 수 없습니다.

바꾸신 Dockerfile 을 저장소에 돌려주시면 저희가 그 위에서 이어 가겠습니다. 두 벌이 되면 어느 쪽이 배포된 것인지 알 수 없어집니다.
