# 추천 AI 서버와 백엔드의 API 명세

**정하는 것**: 추천 AI 서버와 백엔드가 주고받는 API 전부 — 백엔드가 열어 줄 두 개와 AI 서버가 여는 여섯 개의 요청·응답 모양, 필드마다 없을 때 생기는 일, 알레르기 라벨의 처리, 공통 규약, 그리고 각 항목이 지금 코드에 있는지 합의 뒤에 만드는지

**적용 대상**: 백엔드 개발자. 추천 엔진(파트 B)과 데이터 파트(A)는 계약의 정본으로 봅니다

**버전**: 2.0.0 · **최종 수정**: 2026-09-21 · **작성자**: 유재현

---

## 1. 전제

**AI 서버는 백엔드 DB 에 직접 붙지 않습니다.** 운영에서 쓰는 모든 실데이터는 이 문서의 API 로만 오갑니다.

2026-09-21 에 받은 덤프(레시피 21,491건 · 재료 148종)는 **테스트용 표본**입니다. 엔진을 실제 모양의 데이터로 돌려 보려고 받은 것이고 운영 데이터가 아닙니다. 이 문서에 나오는 건수와 비율은 전부 그 표본에서 잰 것이며, 설계를 정한 근거로만 씁니다. 필드 이름은 그 덤프의 컬럼명을 그대로 따랐습니다. 이미 있는 이름을 바꾸자는 제안이 아닙니다.

읽는 법 두 가지입니다.

- 표의 **"없으면"** 칸이 가장 중요합니다. 빠진 값은 에러를 내지 않고 그 신호만 조용히 꺼집니다. 추천은 계속 200 으로 나가고 품질만 떨어지므로, 무엇이 꺼지는지 미리 적어 둡니다.
- **구현 상태**를 항목마다 적었습니다. `있음` 은 지금 코드에 있는 것이고 `합의 후` 는 이 명세에 동의해 주시면 만드는 것입니다. AI 서버는 **모르는 필드가 오면 요청 전체를 400 으로 거부**하므로, `합의 후` 필드를 먼저 보내시면 실패합니다.

## 2. 누가 무엇의 주인인가

| 데이터 | 주인 | AI 서버가 받는 방법 |
|---|---|---|
| 레시피 · 재료 사전 | 백엔드 | AI 가 하루 한 번 당겨 가 메모리에 둡니다 (3절) |
| 사용자의 냉장고 · 알레르기 | 백엔드 | **추천 요청마다 동봉**합니다 (4.4) |
| 온보딩 응답 — 고른 음식 · 맛 척도 · 좋아하는 음식 유형 | 백엔드가 받아 AI 에 전달 | `POST /v1/onboarding/{user_id}` (4.3) |
| 취향 벡터 · 추천 로그 · 행동 이벤트 | AI | AI 가 자기 DB 에 저장합니다 |
| 레시피의 파생값 — 맛 6축 · 재료 희소도 · 군집 | AI | 받은 레시피에서 AI 가 계산합니다 |

나누는 기준은 하나입니다. **백엔드가 주인인 데이터는 AI 가 사본을 오래 들고 있지 않습니다.** 냉장고와 알레르기를 AI 쪽에 따로 저장하면 동기화가 한 번 실패했을 때 옛 냉장고로 추천이 나가는데 에러가 없습니다. 알레르기는 그 일이 생기면 안 되는 자리입니다. 그래서 요청마다 받습니다.

레시피는 반대입니다. 전량을 엔진 모델로 바꾸면 4.2MB 라 메모리에 다 올라가고, 추천 한 번이 후보 500건을 보므로 매번 API 로 받으면 왕복마다 수백 KB 가 오갑니다. 점수 계산과 재정렬이 후보 500건에 이미 48ms 를 쓰므로 그 위에 왕복을 얹지 않습니다.

```text
[하루 1회]  AI ──── GET /internal/ai/ingredients ────▶ 백엔드
            AI ──── GET /internal/ai/recipes ─────────▶ 백엔드     AI 가 맛·희소도를 계산해 캐시

[가입 때]   백엔드 ─ GET  /v1/onboarding/presented ───▶ AI         화면에 그릴 음식 20개
            백엔드 ─ POST /v1/onboarding/{user_id} ───▶ AI         고른 음식 · 맛 척도 · 음식 유형

[추천 때]   백엔드 ─ POST /v1/recommend ──────────────▶ AI         냉장고 · 알레르기 동봉
            백엔드 ◀ recipe_id 목록 · 순위 · 이유 ───── AI         백엔드가 제목·썸네일을 붙여 화면에

[행동 때]   백엔드 ─ POST /v1/events ─────────────────▶ AI         조회 · 저장 · 조리 · 평점
```

## 3. 백엔드가 열어 주실 API

둘 다 **구현 상태: 신규**입니다. AI 서버가 호출하는 읽기 전용 엔드포인트입니다. 경로는 제안이고 편하신 대로 정해 주십시오.

### 3.1 재료 사전

```text
GET {BACKEND}/internal/ai/ingredients
```

```json
{
  "items": [
    {
      "ingredient_id": 1,
      "name": "마늘",
      "category": "채소류",
      "default_storage_type": "REFRIGERATED",
      "default_shelf_life_days": 30,
      "extended_consumption_days": 30,
      "is_staple": false,
      "allergens": []
    }
  ]
}
```

| 필드 | 필수 | 쓰는 곳 | 없으면 |
|---|---|---|---|
| `ingredient_id` · `name` | 예 | 매칭의 키, 부족 재료 문구, 알레르기 전개 | 추천이 동작하지 않습니다 |
| `category` | 아니요 | 맛 추정의 기본값 | 그 재료가 맛에 기여하지 않는 것으로 처리됩니다 |
| `default_shelf_life_days` | 예 | 소비기한 추정 | 사용자가 날짜를 직접 넣지 않으면 임박 판정을 못 합니다 |
| `extended_consumption_days` | 아니요 | 소비기한 경과 후 표시 | 유통기한과 소비기한을 구분하지 못합니다 |
| `is_staple` | **요청** | 상비 재료 자동 포함 | 지금은 AI 쪽 사전으로 대신합니다(148종 중 23종 — 간장·설탕·소금·식용유 등). 빈도로 짐작하면 마늘·양파·대파가 상비로 들어가 없는 재료를 있다고 치게 됩니다 |
| `allergens` | **요청** | 알레르기 하드컷 | 지금은 AI 쪽 사전으로 대신합니다(5절). **배열이어야 합니다** — 간장은 대두이면서 밀입니다 |

### 3.2 레시피

```text
GET {BACKEND}/internal/ai/recipes?updated_after=2026-09-21T00:00:00Z&cursor=&limit=1000
```

```json
{
  "items": [
    {
      "recipe_id": 1,
      "title": "카레 맛있게 만드는 집밥레시피",
      "cuisine_type": "KOREAN",
      "cooking_time": 30,
      "servings": 4,
      "difficulty": "EASY",
      "is_published": true,
      "updated_at": "2026-08-31T01:09:30Z",
      "ingredients": [
        {"ingredient_id": 37, "name": "소고기", "is_main": true, "unit": "g"},
        {"ingredient_id": 24, "name": "감자", "is_main": true, "unit": "개"}
      ],
      "popularity": {"view_count": 0, "scrap_count": 0, "order_count": 0},
      "rating": {"average": null, "count": 0}
    }
  ],
  "next_cursor": "eyJpZCI6MTAwMH0=",
  "total": 21491
}
```

| 필드 | 필수 | 쓰는 곳 | 없으면 |
|---|---|---|---|
| `recipe_id` | 예 | 모든 곳의 키 | 동기화가 안 됩니다 |
| `title` | 예 | 맛 강도 추정, **알레르기 2차 방어선**(5.4) | 재료 행이 빠진 레시피를 못 걸러 냅니다 |
| `cuisine_type` | 예 | 음식 유형 신호와 유형 칸 | 온보딩의 "좋아하는 음식 유형" 이 목록에 닿지 않습니다 |
| `cooking_time` | 예 | 조리시간 상한 필터 | "30분 안에" 요청을 거를 수 없습니다 |
| `difficulty` | 아니요 | 난이도 신호 | 그 신호만 꺼집니다. 표본에서 94.5%가 `EASY` 라 변별력은 낮습니다 |
| `is_published` | 예 | 후보에서 제외 | 미공개 레시피가 추천에 섞입니다 |
| `ingredients[].ingredient_id` | 예 | 재료 매칭 전부 | 추천이 동작하지 않습니다 |
| `ingredients[].is_main` | 예 | 필수 재료 판정, 부족 재료 계산 | 전 재료를 필수로 보게 되어 만들 수 있는 레시피가 거의 없어집니다 |
| `ingredients[].unit` | 아니요 | 맛 강도 추정 | 추정이 거칠어집니다. 단위 종류만 보고 수량은 안 봅니다 |
| `popularity.*` | **요청** | 인기 신호 (순위 가중치 0.10) | 지금 상태입니다. 인기 신호가 통째로 꺼져 있고, **신규 사용자의 첫 화면이 사실상 임의**입니다(7.1) |
| `rating.*` | **요청** | 품질 신호 | 품질 신호가 꺼집니다 |
| `updated_at` | 예 | 증분 동기화 | 매번 전량을 받아야 합니다 |

세 가지를 부탁드립니다.

- `ingredients` 배열은 **레시피에 적힌 순서 그대로** 주십시오. 한국 레시피는 주재료를 앞에 적는 관행이 있어 맛 추정이 그 순서를 신호로 씁니다.
- 증분 응답(`updated_after`)에는 **비공개로 바뀌었거나 지워진 레시피도** `is_published: false` 로 실어 주십시오. 그래야 AI 의 캐시에서 빠집니다. 안 실리면 지워진 레시피가 계속 추천됩니다.
- 제목·썸네일·조리 단계는 AI 가 화면용으로 돌려드리지 않습니다(4.4). 추천 응답의 `recipe_id` 로 백엔드 DB 에서 붙여 주십시오.

## 4. AI 서버가 여는 API

전부 `X-Internal-Api-Key` 헤더가 필요합니다. 예외는 4.6 의 `live` · `ready` 둘입니다.

### 4.1 온보딩 제시 목록

**구현 상태: 있음.** 온보딩 화면에 보여 줄 음식 스무 개입니다.

```text
GET {AI}/v1/onboarding/presented
```

```json
{
  "list_version": 2,
  "items": [
    {"name": "오징어볶음", "family": "korean"},
    {"name": "불고기", "family": "korean"}
  ]
}
```

**이 목록을 복사해 두지 마십시오.** 목록은 바뀝니다. 화면을 그리기 직전에 받고, 사용자가 고른 것을 `name` 으로 돌려보내 주십시오. 번호(자리)로 보내면 목록이 바뀐 날부터 같은 번호가 다른 음식을 가리키는데 에러가 나지 않습니다.

### 4.2 맛 척도의 이름과 범위

**구현 상태: 있음.**

```text
GET {AI}/v1/onboarding/taste-axes
```

```json
{
  "axes": [
    {"key": "spicy", "label": "매움"},
    {"key": "salty", "label": "짠맛"},
    {"key": "sweet", "label": "단맛"}
  ],
  "min": 1,
  "max": 5
}
```

### 4.3 온보딩 저장

**구현 상태: 있음.** 온보딩 응답을 받아 취향을 계산하고 저장합니다.

```text
POST {AI}/v1/onboarding/{user_id}
```

```json
{
  "picks": ["오징어볶음", "불고기", "계란말이"],
  "taste_preferences": {"spicy": 4, "salty": 3, "sweet": 2},
  "preferred_cuisines": ["한식", "일식"],
  "allergy_groups": ["우유", "땅콩", "아황산류"],
  "household_size": 2
}
```

```json
{
  "user_id": 1024,
  "taste": {"spicy": 0.75, "salty": 0.5, "sweet": 0.25},
  "preferred_cuisines": ["korean", "japanese"],
  "allergy_groups": ["dairy", "nut"],
  "unmapped_allergens": ["아황산류"],
  "n_blocked_ingredients": 24
}
```

| 필드 | 필수 | 뜻 | 없으면 · 틀리면 |
|---|---|---|---|
| `picks` | 예 (1~20개) | 4.1 에서 받은 `name` | 목록에 없는 이름이면 **요청을 거부**합니다. 가까운 음식으로 짐작하면 고르지 않은 것이 취향이 됩니다 |
| `taste_preferences` | 아니요 | 4.2 의 `key` 세 개, 각 1~5 | 고른 음식만으로 취향을 만듭니다. **배열로 보내지 마십시오** — 순서가 어긋나도 숫자 세 개는 통과합니다 |
| `preferred_cuisines` | 아니요 (최대 5) | `한식` · `중식` · `일식` · `양식` · `아시안`, 또는 코드 `korean` · `chinese` · `japanese` · `western` · `asian_other` | 모르는 값이면 **요청을 거부**합니다 |
| `allergy_groups` | 아니요 | 5절의 라벨 | 모르는 라벨은 거부하지 않고 `unmapped_allergens` 로 돌려드립니다 |
| `household_size` | 아니요 | 1~10 | 지금은 저장만 합니다 |

응답의 `unmapped_allergens` 가 비어 있지 않으면 **그만큼 차단되지 않은 것**입니다. 사용자에게 알리거나 저희에게 그 라벨을 알려 주십시오.

알레르기는 4.4 에서 요청마다 다시 받습니다. 둘 다 오면 **추천 요청의 것이 이깁니다** — 백엔드 DB 가 정본이기 때문입니다.

### 4.4 추천

```text
POST {AI}/v1/recommend
```

```json
{
  "user_id": 1024,
  "session_id": "c-1024-8f3a2b1c9d0e",
  "top_k": 20,
  "max_minutes": 30,
  "include_trace": false,
  "pantry": [
    {"ingredient_id": 37, "quantity": 300, "unit": "g",
     "purchased_at": "2026-09-18", "expires_at": "2026-09-23"},
    {"ingredient_id": 5, "purchased_at": "2026-09-20"}
  ],
  "allergies": ["우유", "땅콩"]
}
```

| 필드 | 상태 | 필수 | 쓰는 곳 | 없으면 |
|---|---|---|---|---|
| `user_id` | 있음 | 예 | 취향과 로그의 키 | 요청 거부 |
| `session_id` | 있음 | 아니요 | 로그 분석 | 세션 단위 분석을 못 합니다. `c-` 실사용자 · `g-` 게스트 · `d-` 개발 로 시작해야 합니다 |
| `top_k` | 있음 | 아니요 (기본 20, 1~100) | 목록 길이 | |
| `max_missing` | 있음 | 아니요 (기본 2, 0~10) | 부족 재료 허용 수 | |
| `max_minutes` | 있음 | 아니요 | 조리시간 상한 | 상한 없이 추천합니다 |
| `include_trace` | 있음 | 아니요 (기본 true) | 응답에 추적 정보를 실을지 | **운영에서는 `false` 로 보내 주십시오.** 응답이 크게 줄어듭니다 |
| `pantry[]` | **합의 후** | 예 | 재료 매칭 | 냉장고가 빈 것으로 보고 인기순으로 냅니다 |
| `pantry[].expires_at` | **합의 후** | 아니요 | 임박 재료 가산 (가중치 0.15) | `purchased_at` 과 재료 사전의 소비기한으로 추정합니다. 둘 다 없으면 임박 신호가 꺼집니다 |
| `allergies[]` | **합의 후** | 아니요 | 하드컷 | **알레르기 재료가 추천에 섞입니다.** 빈 배열과 생략은 같은 뜻으로 봅니다 |

`pantry` 에는 **사용자가 직접 넣은 것만** 담아 주십시오. 소금·간장 같은 상비 재료는 AI 가 자동으로 더합니다. 그 구분으로 "냉장고가 사실상 비었는가" 를 판정합니다. 상비 재료만 있는 사용자에게 재료 매칭을 돌리면 양념 만드는 법만 나오기 때문에, 그때는 인기순으로 냅니다.

지금 코드에는 냉장고를 미리 밀어 두는 길(`PUT /v1/users/{user_id}/pantry`)도 있습니다. 그 방식은 동기화가 한 번 실패하면 옛 냉장고로 추천이 나가는데 에러가 없어, 동봉을 권합니다(8절).

응답입니다.

```json
{
  "contract_version": "v1",
  "request_id": "75f2aab5-9792-44fb-8996-175b6aa61cf8",
  "user_id": 1024,
  "model_version": "reco-v0",
  "served_at": "2026-09-21T10:00:00Z",
  "items": [
    {
      "recipe_id": 8821,
      "final_rank": 1,
      "reason": "두부(D-3)를 소진할 수 있고, 냉장고 재료를 11가지나 써요",
      "coverage": 1.0,
      "missing_count": 0,
      "missing_ids": []
    }
  ]
}
```

| 화면에 쓰실 필드 | 뜻 |
|---|---|
| `request_id` | **이벤트를 보낼 때 이 값을 함께 주십시오.** 노출과 반응을 잇는 유일한 열쇠입니다 |
| `items[].recipe_id` | 백엔드 DB 에서 제목·썸네일을 붙이는 키 |
| `items[].final_rank` | 화면에 보이는 순서. 1부터입니다. **이 순서를 바꾸지 마십시오** |
| `items[].reason` | 한국어 한 문장. AI 가 만듭니다 |
| `items[].missing_ids` | 부족한 필수 재료의 `ingredient_id`. 장보기로 잇는 자리입니다 |
| `items[].coverage` | 필수 재료 충족률 0~1 |

응답에는 이 밖에도 필드가 더 실려 옵니다 — `features`(신호 17종) · `score` · `propensity` · `is_exploration` · `is_cuisine_slot` · `weights` 등입니다. 전부 **평가와 디버깅용이라 무시하셔도 됩니다.** 다만 하나는 지켜 주십시오.

**`is_exploration` 이 `true` 인 항목을 걸러 내거나 뒤로 보내지 마십시오.** 목록의 20%는 일부러 섞은 "새로운 시도" 입니다. 클라이언트가 그 칸을 빼면 사용자의 숨은 취향을 찾지 못하고, 그 효과를 영영 측정하지 못합니다.

### 4.5 행동 이벤트

**구현 상태: 있음.** 한 번에 1~200건입니다.

```text
POST {AI}/v1/events
```

```json
{
  "events": [
    {
      "user_id": 1024,
      "event_type": "cook",
      "recipe_id": 8821,
      "request_id": "75f2aab5-9792-44fb-8996-175b6aa61cf8",
      "position": 1,
      "occurred_at": "2026-09-21T19:32:11+09:00"
    }
  ]
}
```

```json
{"accepted": 1, "rejected": 0, "errors": []}
```

| 필드 | 필수 | 뜻 |
|---|---|---|
| `event_type` | 예 | `impression` · `click` · `save` · `unsave` · `cook` · `rating` · `dismiss` · `search`. 소문자이며 **뜻을 바꾸거나 지울 수 없습니다** — 과거 로그가 그 뜻으로 쌓입니다 |
| `recipe_id` | `search` 가 아니면 예 | |
| `request_id` | 추천에서 나온 행동이면 예 | 4.4 응답의 값. 없으면 그 행동을 어느 추천의 결과로도 셀 수 없습니다 |
| `position` | 아니요 | 목록에서 몇 번째였는가 (`final_rank`) |
| `value` | `rating` 이면 예 | 평점, 또는 머문 시간(초) |
| `occurred_at` | 아니요 | **시간대가 반드시 있어야 합니다.** 없으면 요청을 거부합니다 |

`impression`(노출)은 보내지 않으셔도 됩니다. 추천 응답을 낼 때 AI 가 스스로 기록합니다.

`occurred_at` 은 선택이고 없으면 AI 가 받은 시각을 씁니다. **오프라인에서 모아 두었다가 한 번에 보내실 때는 반드시 실어 주십시오.** 200건이 같은 시각을 받으면 최근 행동에 무게를 더 주는 계산이 뭉개집니다.

취향은 `cook` · `save` · `rating` · `click` 에서 배웁니다. 이 이벤트가 쌓여야 "선호 재료" 와 "재료 궁합" 신호(순위 가중치 0.21)가 켜집니다. 지금은 꺼져 있습니다.

|---|---|---|
| `GET /health/live` | 불필요 | 프로세스가 살아 있는가 |

## 5. 알레르기

### 5.1 받는 모양

백엔드 DB 의 값을 **한글 라벨 그대로** 주시면 됩니다.

```json
{"allergies": ["우유", "땅콩"]}
```

### 5.2 라벨과 막는 범위

식약처 표시 대상 표기를 그대로 받고 괄호와 공백이 있어도 읽습니다. 영문 코드도 같은 자리에서 받습니다. 아래 "막는 범위" 는 표본 재료 148종 기준입니다.

| 받는 라벨 | 코드 | 막는 범위 |
|---|---|---|
| `알류(가금류)` · `알류` · 난류 · 달걀 · 계란 | `egg` | 달걀 · 메추리알 · 마요네즈 |
| `우유` · 유제품 · 치즈 · 버터 | `dairy` | 우유 · 버터 · 생크림 · 연유 · 요거트 · 치즈류 · 초콜릿 |
| `땅콩` · `호두` · `잣` · `견과류` · 아몬드 | `nut` | 견과 전부 |
| `대두` · 콩 · 두부 | `soy` | 두부 · 콩나물 · 간장 · 고추장 · 된장 |
| `밀` · 밀가루 · 글루텐 | `gluten` | 밀가루 · 식빵 · 면류 · 부침가루 · 튀김가루 · 빵가루 · 만두 · 또띠아 · 돈가스소스 |
| `메밀` | `buckwheat` | 표본 사전에 해당 재료가 없습니다 |
| `참깨` · 깨 · 들깨 | `sesame` | 통깨 · 참기름 · 들기름 · 들깨가루 |
| `고등어` · 생선 · 어류 | `fish` | 고등어 · 멸치 · 참치 · 어묵 · 액젓 · 맛살 · 북어 · 명란젓 · 참치액 |
| `게` · `새우` · `조개류(굴,전복,홍합 포함)` · `조개류` · 갑각류 · 굴 · 전복 · 홍합 | `shellfish` | 새우 · 건새우 · 새우젓 · 바지락 · 굴 · 굴소스 · 김치(젓갈) |
| `오징어` · 낙지 · 문어 · 주꾸미 · 연체류 | `mollusk` | 오징어 · 진미채 |
| `복숭아` | `peach` | 표본 사전에 해당 재료가 없습니다 |
| 해산물 | (셋) | `fish` + `shellfish` + `mollusk` |
| `돼지고기` · `쇠고기` · `닭고기` · `토마토` | 없음 | 재료 이름으로 막습니다 — 그 고기와 가공품(베이컨·햄·소시지·스팸), 토마토·케첩·토마토소스 |
| `아황산류` | 없음 | **막지 못합니다.** 가공 첨가물이라 재료 사전에 표제어가 없습니다. 모르는 라벨로 돌려드립니다 |

코드 글꼴로 적은 라벨이 계약 어휘(`src/features/recommend/enums.py` 의 `ALLERGEN_LABELS`)이고, 나머지는 같은 뜻으로 받는 다른 말입니다.

### 5.3 세 가지 원칙

**군 전체를 막습니다.** "땅콩" 을 고르면 호두까지, "새우" 를 고르면 조개류와 김치(젓갈)까지 막습니다. 덜 막아서 생기는 일과 더 막아서 생기는 일의 무게가 다릅니다.

**군의 경계는 넘지 않습니다.** 오징어·낙지(두족류)는 갑각류·조개류와 다른 알레르기입니다. 새우를 고른 사용자에게서 오징어까지 빼지 않습니다.

**모르는 라벨은 버리지 않습니다.** 표에 없는 라벨이 오면 아는 것은 그대로 막고, 모르는 것은 온보딩 응답의 `unmapped_allergens` 로 돌려드리며 로그에 남깁니다. 조용히 버리면 그 사용자는 보호받지 못하는데 응답은 200 입니다. **백엔드가 쓰는 라벨 전체 목록을 한 번 보내 주십시오.** 표에 없는 것을 미리 더해 두겠습니다.

### 5.4 재료 목록만 믿지 않습니다

표본에 **제목에는 있는데 재료 행에는 없는** 레시피가 있었습니다. 새우 알레르기를 넣고 돌렸더니 1위가 「고추장 건새우볶음」 이었습니다. 그 레시피(`recipe_id` 1194)의 `recipe_ingredients` 에는 다진마늘·고춧가루·고추장 등 아홉 줄이 있고 **건새우가 없습니다.**

| 제목에 이 말이 있는 레시피 | 그중 재료 행에 그 재료가 없는 것 |
|---|---|
| 새우 618건 | 17건 (2.8%) |
| 오징어 669건 | 52건 (7.8%) |
| 땅콩 31건 | 4건 (12.9%) |
| 우유·치즈·버터·크림 1,179건 | 46건 (3.9%) |
| 달걀·계란 1,446건 | 22건 (1.5%) |

그래서 AI 는 재료 id 와 함께 **제목**도 봅니다. 제목에 막힌 재료의 이름이나 그 다른 말(계란 · 에그 · 쉬림프 · 피넛 · 크림 · 제육)이 있으면 재료 행에 없어도 막습니다. 넓게 걸립니다 — "노밀가루 홈베이킹" 처럼 그 재료가 없다고 적은 제목도 막힙니다. 부정 표현을 읽으려 들지 않았습니다. 잘못 읽으면 그 방향이 위험합니다.

다만 **제목에도 재료가 안 적힌 레시피는 여전히 못 잡습니다.** 운영 데이터에서 떨어진 재료 행을 복구할 수 있는지 봐 주십시오(7.3).

### 5.5 아직 못 막는 것

가공품 안의 다른 알레르기입니다. 간장은 대두이면서 밀이고 굴소스에는 대두가 들어가지만, AI 쪽 사전은 재료마다 알레르기를 하나만 달고 있습니다. **밀 알레르기 사용자에게 간장이 든 레시피가 나갑니다.** 닫으려면 재료 사전에 `allergens` 배열(3.1)이 있어야 하고, 그 정본은 백엔드에 두는 편이 안전합니다.

## 7. 백엔드 데이터에 부탁드리는 것

표본으로 엔진을 끝까지 돌려 확인한 것입니다. 운영 데이터가 같은 모양이면 같은 일이 생깁니다.

### 7.1 인기 신호

조회수·스크랩·주문·평점이 표본에 하나도 없었습니다(`recipe_scraps` 0건). 순위 가중치의 0.10 이 통째로 꺼져 있습니다. 특히 **냉장고가 빈 신규 사용자는 "인기순" 으로 받는데 인기 데이터가 없어 이름만 인기순**입니다.

셋 중 하나만 주셔도 켜집니다. 조회수가 가장 구하기 쉽고, 스크랩 수가 가장 정확하며, 주문 수가 가장 사업에 가깝습니다. 원값 그대로 주시면 되고 정규화는 AI 가 합니다.

### 7.2 재료별 알레르기와 상비 표시

3.1 의 `allergens`(배열)와 `is_staple` 입니다. 지금은 둘 다 AI 쪽 사전에서 이름으로 이어 씁니다. 알레르기는 틀리면 사람이 다치는 자리인데 판정 근거가 한쪽에만 있습니다.

### 7.3 빠진 재료 행

5.4 입니다. 재료 사전에 닿지 못한 재료가 정규화 과정에서 떨어진 것으로 보입니다. 추천 품질에도 나쁘지만 알레르기 차단에 구멍이 납니다.

### 7.4 비슷한 레시피

제목이 완전히 같은 레시피가 782건, 필수 재료가 같은 묶음이 2,285개(가장 큰 묶음 115건)였습니다. 추천 스무 칸에 두부조림 변형이 네 개 들어간 적이 있습니다. 같은 레시피의 판본을 묶는 대표 번호가 있으면 가장 깔끔합니다. 없으면 AI 쪽 재정렬에서 막는 길을 찾겠습니다.

### 7.5 맛 정보는 필요 없습니다

표본에 맛 정보가 없었지만 맛은 재료에서 나오므로 AI 가 계산합니다. 표본 재료 148종이 전부 AI 의 맛 사전에 닿았고, 복원한 값이 다른 데이터로 계산한 값과 0.023 안에서 일치했습니다. 3.2 의 `unit` 과 재료 순서만 주시면 됩니다.
