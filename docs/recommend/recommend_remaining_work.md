## 3. 다른 파트에 요청할 것

파트마다 둘로 나눕니다. **로컬 테스트** 는 그 파트가 자기 PC 에서 붙여 볼 때 필요한 것이고, **클라우드 배포** 는 운영에서 돌기 위해 필요한 것입니다. 표의 "없으면" 칸은 그 요청이 빠졌을 때 생기는 일이며 전부 에러 없이 생깁니다. Notion 전달본은 이 절을 옮긴 것이되 **저장소 문서의 절 번호 같은, 그쪽에서 열 수 없는 참조는 뺐습니다.**

### 3.1 백엔드 — 로컬 테스트

백엔드 개발자가 자기 PC 에서 AI 서버를 띄워 두 API 와 추천 호출을 붙여 볼 때입니다. 필요한 것은 Docker 하나입니다(또는 Python 3.12 + `uv`).

```bash
docker build -t reco-ai-server .        # 저장소 루트에서(main). 약 2.6GB, 수 분
docker run --rm -p 8000:8000 \
  -e DB_HOST=localhost -e DB_NAME=x -e DB_USER=x -e DB_PASSWORD=x \   # 추천은 DB 를 안 읽습니다. 자리 채움이면 됩니다
  -e GEMINI_API_KEY=dummy \                                          # 영수증 기능만 씁니다
  -e INTERNAL_API_KEY=<백엔드와 같은 값> \
  -e BACKEND_BASE_URL=http://host.docker.internal:8080 \             # 호스트에서 도는 백엔드
  -v reco-var:/app/var \
  reco-ai-server
```

| ID | 요구사항 | 비고 |
|---|---|---|
| B-L1 | 백엔드의 두 API 가 호스트에서 떠 있고 AI 컨테이너에서 닿을 것 | Docker Desktop(Windows · Mac)은 `host.docker.internal` 로 호스트에 닿습니다. Linux 는 `--add-host host.docker.internal:host-gateway` |
| B-L2 | 두 API 가 `X-Internal-Api-Key` 헤더의 값이 `INTERNAL_API_KEY` 와 같을 때만 200 | 로컬에서는 아무 문자열이나 양쪽에 같게 |
| B-L3 | 응답 모양 — 래퍼 없이 최상위 `items`, 레시피는 `next_cursor`(끝이면 null) | 래퍼가 있으면 `catalog sync failed` |
| B-L4 | 추천 요청의 `pantry[].ingredient_id` 를 **자기 재료 사전의 번호**로, `allergies` 는 한글 라벨로 | 사전에 없는 번호는 조용히 빠집니다 |
| B-L5 | 백엔드 없이 프론트만 붙여 볼 때는 `BACKEND_BASE_URL` 을 빼고 띄우면 목업이 답함(200, 가짜 번호) | 계약 모양은 같습니다 |

| 확인 | 기대 | 아니면 |
|---|---|---|
| 기동 로그 | `aiServer started (... recommend=live)` 그리고 수 초 뒤 `catalog synced version=... recipes=N` | `recommend=mock` 이면 `BACKEND_BASE_URL` 이 안 들어간 것. `catalog sync failed: ...` 면 주소 · 키 · 경로 · 응답 모양(래퍼 없이 최상위 `items`) |
| `GET /health`(헤더 `X-Internal-Api-Key`) | `model_version` 이 `reco-b-linear-v0` | `mock-linear-v0` 이면 목업 |
| `GET /metrics`(같은 헤더) | `reco_catalog_ready 1` · `reco_catalog_recipes N` | 0 이면 아직 못 받음 → 추천 503 |
| `POST /v1/recommend` | 200, `items[].recipe_id` 가 **백엔드 DB 의 번호** | 503 이면 사전 없음. 400 이면 본문의 `fields` 에 어느 필드가 왜 |
