## 2. 두 형식 규칙 (파트 B 기본 규칙)

파트 B 에서는 **어떤 작업이든 기록이 필요하다고 판단한 결과를 두 형식으로 남깁니다.** 에이전트용이 먼저이고 사람용은 그 서술본입니다.

| 항목 | 에이전트용 | 사람용 |
|---|---|---|
| 위치 | 이 폴더 바로 아래 | `human/` 아래, 같은 파일명 |
| 정본 | 작업 기록은 에이전트용이 정본 | 명세(사람이 쓴 것)는 사람용이 정본 |
| 형식 | 표, 키-값, 식별자. 문장은 최소. 경로·심볼·명령은 그대로 | 문장과 단락. 식별자를 괄호로 함께 적어 대응 |
| 기준 | 사람이 **확인만 가능**하면 충분 | 배경을 모르는 팀원이 읽고 이해할 수 있어야 함 |
| 헤더·본문 형식 | `02_DIRECTORY_STRUCTURE.md` 2.5 를 따름 | 같음 |
| 식별자 | D 결정 · A 가정 · I 접점 · T 계획 항목 · P 선행 조건 · C 고려사항 · E 환경. 번호는 재사용하지 않고 폐기는 표기로 남김 | 에이전트용의 식별자를 그대로 참조 |

갱신 순서는 **작업 → 에이전트용 갱신 → 사람용 갱신 → 같은 커밋(`docs(plan): ...`)** 입니다. 두 파일의 식별자 집합이 같은지 아래 명령으로 확인합니다. 출력이 없으면 일치합니다.

```bash
diff <(grep -oE '\b[DAITPCE]-[0-9]{2}\b' docs/plan/PM_ENG_RECO_B_001_worklog.md | sort -u) \
     <(grep -oE '\b[DAITPCE]-[0-9]{2}\b' docs/plan/human/PM_ENG_RECO_B_001_worklog.md | sort -u)
```

에이전트용에만 있는 식별자는 사람용에 문장을 더해 채우고, 사람용에만 있는 식별자는 오타입니다.

## 3. 세션 종료 절차

1. 에이전트용 작업 기록의 1절(상태 요약)을 갱신합니다.
2. 3절(실행된 것), 4절(실행되어야 할 것), 9절(세션 기록)을 갱신합니다. 새 결정·가정·항목은 다음 번호를 받습니다.
3. 사람용 서술본을 갱신합니다. 새 식별자마다 문장이 있어야 합니다.
4. 2절의 식별자 대조 명령을 실행합니다.
5. `uv run ruff format --check docs/plan` 을 실행합니다. 코드블록도 검사 대상입니다.
6. `docs(plan): <무엇을 기록했는가>` 로 커밋합니다. 코드 커밋과 섞지 않습니다.

## 구성 근거

에이전트용을 정본으로 둔 이유는 기록의 주된 독자가 다음 세션의 에이전트이기 때문입니다. 에이전트는 표와 식별자에서 상태를 빠르게 복원하지만, 서술문에서는 무엇이 결정이고 무엇이 배경인지 다시 분류해야 합니다. 반대로 사람은 표만 보면 맥락을 잃습니다. 같은 사실을 두 번 쓰는 비용보다, 한쪽 독자가 매번 번역하는 비용이 큽니다.

명세는 방향이 반대입니다. 사람이 쓰고 사람이 승인하는 문서라 원본이 정본이고, 에이전트용은 읽기 비용을 줄이는 압축본입니다. 이 관계는 저장소 루트의 `CLAUDE.md` 와 `docs/convention/` 원문의 관계와 같습니다.

식별자를 둔 이유는 두 형식이 어긋나는 것을 기계적으로 잡기 위해서입니다. 문장 대조는 사람이 해야 하지만 식별자 집합의 대조는 명령 한 줄입니다.
