### 2.6 파트 C (평가) 에게

> 병합: **2026-09-16 18:03 KST · PR #9 · merge commit `77da2bc`**

**1. 추천 로그에 칸이 늘었습니다.** 아이템마다 `is_cuisine_slot` 이 붙습니다.

- **탐색 칸과 섞지 마십시오.** 탐색은 무작위라 노출 확률이 1 보다 작고 IPS 보정의 근거가 됩니다. 유형 칸은 결정적이라 노출 확률이 **1.0** 입니다. 한 칸으로 합치면 분모가 섞여 사후에 다시 나눌 수 없습니다.
- 한 아이템이 두 몫을 겸하지 않습니다(불변식으로 검사합니다).

**2. 추적 파라미터 네 개가 덧붙습니다.** 음식 유형을 고른 사용자의 요청에만 실립니다.

| 키 | 뜻 |
|---|---|
| `n_cuisine` | 이번 목록에서 유형 몫으로 뗀 칸 수 (0~2) |
| `cuisine_slot_ratio` | 그때 쓴 비율 손잡이 (기본 0.1) |
| `preferred_cuisines` | 그 사용자가 고른 유형 (쉼표로 이은 코드) |
| `cuisine_unmet` | 고른 유형 가운데 **목록에 끝내 없던 것.** 이 값이 계속 차 있으면 후보 쪽 문제입니다 |

**3. 페르소나 상태 값의 뜻.** `persona_mode` 는 `onboarding` · `blended` · `behavior` 셋이고, 이벤트 건수가 아니라 시각 가중을 반영한 무게로 정합니다.

시뮬 시드의 `user_vector.computed_from` 은 건수 기준이라 둘이 같지 않습니다 — 배치 검증에서 시드 값을 그대로 기대값으로 쓰지 마십시오. 실제로 시드 기준 `behavior` 235명이 엔진에서는 195/40 으로 갈렸습니다.

**4. 평가 리허설에 쓸 수 있는 것.** 가상 사용자 1,600명 시드가 저장소에 들어갔습니다. DB 에 적재하는 경로와, DB 없이 엔진에 직접 넣어 돌리는 경로가 둘 다 있습니다(`scripts/sim/`). 절차는 `docs/recommend/recommend_sim_seed_runbook.md` 입니다. **다만 임의로 만든 데이터라 어떤 수치도 '실측' 으로 쓰지 마십시오.**

**5. 아직 서빙 로그를 평가에 쓰지 마십시오.** 라우터가 목업을 부르는 구간이라, 실엔진 이름이 적힌 행이 목업 산출일 수 있습니다. 전환 시점은 별도로 알리겠습니다.

### 2.7 백엔드 · 프론트엔드에게

> 병합: **2026-09-16 18:03 KST · PR #9 · merge commit `77da2bc`**

**1. 온보딩 API 가 문항 하나를 더 받습니다.** `POST /v1/onboarding/{user_id}`

```jsonc
{
  "picks": [0, 3, 11],
  "scales": [2, 3, 1],
  "preferred_cuisines": ["korean", "japanese"],   // 신규 · 선택 · 최대 5개
  "allergy_groups": [],
  "allergy_ingredient_ids": [],
  "avoid_ingredient_ids": [],
  "household_size": 2
}
```

- 값은 `korean` · `chinese` · `japanese` · `western` · `asian_other` 다섯입니다. 한글 라벨(`한식` · `중식` · `일식` · `양식` · `아시안`)로 보내도 받아서 코드로 바꿔 저장합니다.
- **모르는 값은 422 로 거부합니다.** 가까운 유형으로 바꿔 넣지 않습니다 — 사용자가 고르지 않은 유형의 음식이 목록에 오르는데 응답은 200 이 되는 것을 막기 위해서입니다.
- 필드를 안 보내도 됩니다(빈 목록과 같습니다). 기존 요청은 그대로 동작합니다.
- 응답 `OnboardingOut` 에 `preferred_cuisines` 가 추가됩니다. **저장된 코드**를 돌려주므로 라벨로 보냈을 때 무엇이 저장됐는지 확인할 수 있습니다.

**2. 추천 응답 아이템에 `is_cuisine_slot`(boolean) 이 추가됩니다.** 기존 필드는 그대로이니 무시하셔도 됩니다. 화면에서 "고른 유형이라 넣었다" 를 표시하고 싶으면 이 값을 쓰시면 되고, 그 칸의 `reason` 문구는 이미 "즐겨 드시는 중식이고, …" 처럼 나옵니다.

**3. 동작은 아직 목업입니다.** 응답 형식은 계약대로지만 실제 엔진 결과가 아닙니다. 온보딩 값이 실제 추천에 반영되는 시점은 따로 알리겠습니다.

**4. 인증은 그대로입니다.** 모든 업무 경로가 `X-Internal-Api-Key` 헤더를 요구하고, 없으면 401 입니다.
