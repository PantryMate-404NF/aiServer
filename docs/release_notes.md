# 릴리스 노트

**정하는 것**: `main` 에 무엇이 언제 들어갔고, 그것이 어느 파트에 어떤 영향을 주며, 되돌리려면 무엇을 하는가. 파트별 전달 사항을 함께 담습니다

**적용 대상**: 파트 A(데이터) · 파트 C(평가) · 백엔드 · 프론트엔드 · 클라우드 팀. 각 절은 그대로 떼어 전달할 수 있게 자립적으로 씁니다

**버전**: 1.2.0 · **최종 수정**: 2026-09-23 · **작성자**: 유재현

## 1. 읽는 법

2절이 **최신 릴리스**이고 3절이 그 이전입니다. 새 릴리스가 나오면 2절을 3절 맨 앞으로 옮기고 2절을 새로 씁니다 — 절 번호가 흔들리지 않게 이 모양으로 둡니다.

릴리스마다 변경 요약 · 영향 범위 · 롤백 방법을 적고(01의 8절 릴리스 점검표), 그 아래에 파트별 전달 사항을 둡니다. 전달할 때는 해당 절만 복사해 보내면 됩니다 — 절마다 병합 버전과 날짜를 다시 적어 두었습니다.
