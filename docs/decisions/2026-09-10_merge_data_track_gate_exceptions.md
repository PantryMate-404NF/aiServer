# 데이터 파트 병합에서 게이트 예외를 어디까지 허용하는가

**정하는 것**: `origin/develop-data-part` 전량을 `feat/recommend-engine-core` 에 합칠 때, 저장소 게이트(ruff·mypy·pytest)를 통과시키기 위해 무엇을 고치고 무엇을 예외로 두는가

**적용 대상**: 이 병합을 리뷰하는 인원, `pyproject.toml` 의 검사 설정을 고치는 인원, AI 코딩 에이전트

**버전**: 1.0.0 · **최종 수정**: 2026-09-10 · **작성자**: 유재현

---

## 1. 결정

**경계는 "서빙 경로인가" 하나입니다.** 요청을 처리하는 코드는 손으로 고쳐 규칙에 맞췄고, 사람이 한 번 돌려 결과를 읽는 도구는 범위를 좁힌 예외로 두었습니다.

| 대상 | 처리 | 근거 |
|---|---|---|
| `src/**` 전부 | 손으로 고침. ruff 45건, mypy 31건 | 서빙 경로입니다. 예외를 두면 그 예외가 요청 처리 코드에 남습니다 |
| `src/features/recommend/ingest/adapter.py` 의 `ANN401` | 파일 단위 예외 | 모양을 모르는 크롤러 JSON 을 받는 경계입니다. `Any` 가 사실에 맞는 표기입니다 |
| `scripts/reco/bench/**` | 검사 대상에서 제외 (`extend-exclude`) | 일회용 시뮬레이션이고, 일부는 작성자 로컬 경로를 `exec()` 로 읽어 저장소 안에서 돌지 않습니다 |
| `seeds/validate.py`, `scripts/reco/**`, 데이터 파트의 단독 실행 검사 7개 | 파일마다 실제로 필요한 규칙 코드만 예외 | 사람이 터미널에서 읽는 도구입니다. 파일별로 적어 다음에 들어올 파일을 덮지 않게 했습니다 |
| 커버리지 하한 80% | 측정 범위를 축소 (`[tool.coverage.run] omit` 3항목) | 검사가 없는 것이 아니라 그 검사를 pytest 가 아니라 `make` 가 돌립니다 |
| `uv.lock` 의 `pillow-heif` | `main` 값(1.6.0)으로 되돌림 | 이 병합과 무관한 변경이고, 되돌리지 않으면 영수증 파이프라인 검사 8건이 수집 단계에서 죽습니다 |

**전역 `ignore = ["RUF001", "RUF002", "RUF003"]` 은 데이터 파트가 넣은 것을 그대로 두었습니다.** 이것만은 파일 범위가 아니라 저장소 전체에 걸립니다 — 5절을 봅니다.

## 2. 배경

데이터 파트의 브랜치는 자기 `pyproject.toml` 에 이렇게 적어 두었습니다.

> 09-04 현재 ruff·mypy·pytest 게이트는 **아직 통과하지 못한다.** 구조 이식과 규칙 준수를 같은 변경에 섞으면 리뷰가 불가능해져서 설정만 먼저 넣고 코드를 맞추는 것은 다음 작업으로 뺐다.

병합 시점에 실측한 값은 ruff 373건, mypy 31건, 커버리지 46.15% 였습니다. 이 상태로는 `main` 에 병합할 수 없고, 반대로 373건을 전부 손으로 고치면 데이터 파트가 자기 파일을 알아볼 수 없게 됩니다. 그래서 경계를 하나 긋고 그 안쪽만 고쳤습니다.

## 3. 왜 서빙 경로가 경계인가

규칙이 무엇을 막으려는지가 자리마다 다릅니다.

타입 표기(`ANN`)는 **호출자가 계약을 지키게** 하는 장치입니다. 단독 실행 스크립트는 호출자가 사람뿐이고 그 사람이 파일을 열어 읽습니다. 표기를 붙여도 지킬 상대가 없습니다. 반대로 `repository.py` 의 반환형은 스테이지가 읽으므로 표기가 곧 계약입니다.

난수 경고(`S311`)는 **암호에 쓰지 말라**는 것입니다. 시뮬레이션과 목업의 재현용 시드 RNG 는 그 경고의 대상이 아닙니다. 다만 `src/` 안에서는 사유를 같은 줄에 적어 남겼습니다(01의 3.3).

커버리지는 **검사되지 않은 코드를 드러내는** 장치입니다. 데이터 파트의 검사는 실제로 존재하고, 실 DB 가 필요 없는 125건은 이 병합에서 직접 돌려 전부 통과를 확인했습니다(4절). 나머지는 실 DB 가 필요해 확인하지 못했습니다 — 합계 242건이라는 수는 데이터 파트가 `tests/conftest.py` 에 적어 둔 값입니다. 어느 쪽이든 pytest 가 아니라 `make` 가 돌립니다. 이것을 하한선에 넣으면 하한선이 코드 품질이 아니라 어느 도구로 돌렸는가를 재게 됩니다.

## 4. 커버리지에서 뺀 것과 그 검사가 있는 자리

| 뺀 것 | 실제 검사 | 진수 |
|---|---|---|
| `src/features/recommend/ingest/*` | `make normalize-test`, `make contract`, `make feature-test`, `make flavor-check`, `make probe-all` | 병합 시점 실측 — `run` 74건, `test_match` 23건, `test_role` 23건, `test_batch` 5건 통과. `contract` 는 98건 전부 통과이나 `.env` 가 비어 있으면 중간에 멈춥니다(검증 기록 F-30) |
| `src/features/recommend/repository.py` | `make smoke-py`, `make log-test`, `make ddl-test` | 실 DB 가 필요합니다. 01의 6.2 가 단위 테스트에서 실 DB 사용을 금지합니다 |
| `src/features/recommend/engine/mock.py` | `make contract`, `make api-docs` | 대시보드가 엔진을 기다리지 않게 하는 목업입니다 |

축소 후 값은 **88.12%** 입니다(측정 1,734문). `evaluation/threshold.py` 는 일부러 남겨 두었습니다 — 부르는 곳이 없고 검사도 없어 0% 로 잡히며, 그 사실이 보이는 편이 낫습니다(회의 안건 G-17).

## 5. 승인이 필요한 것

01의 3.3 은 전역 ignore 추가에 Tech Lead 승인과 3.1 갱신을 요구하고, 01의 6.1 은 커버리지 하한을 낮추는 설정 변경에 승인과 이 문서를 요구합니다. 아래는 **승인 대기 상태**입니다.

| 항목 | 조항 | 넣은 사람 | 상태 |
|---|---|---|---|
| 전역 `ignore = ["RUF001", "RUF002", "RUF003"]` | 01의 3.3 | 데이터 파트 | 대기. 파트 B 는 이것 없이 통과시키려고 가져온 6개 파일의 수학 기호 21곳을 ASCII 로 고쳤습니다. 승인되면 그 21곳은 되돌려도 됩니다 |
| 파일 단위 예외 10항목 | 01의 3.3 | 파트 B | 대기. `adapter.py` 1 + 도구 9입니다. 병합 전 `per-file-ignores` 는 `main` 의 2항목과 데이터 파트의 2항목이었습니다 |
| `extend-exclude = ["scripts/reco/bench"]` | 01의 3.3 | 파트 B | 대기 |
| 커버리지 측정 범위 축소 3항목 | 01의 6.1 | 파트 B | 대기. 이 문서가 그 기록입니다 |

## 6. 해소 조건

- 파일 단위 예외는 데이터 파트가 자기 도구에 표기를 채우는 만큼 목록에서 줄어듭니다. 목록을 파일별로 적어 둔 이유가 이것입니다.
- 커버리지 축소는 단독 실행 스크립트를 pytest 함수로 옮기면 사라집니다(회의 안건 G-08). 옮기는 즉시 `omit` 에서 빼면 됩니다.
- `scripts/reco/bench` 제외는 그 스크립트들이 로컬 절대경로 대신 저장소 안의 파일을 읽도록 고쳐지면 다시 볼 수 있습니다(G-15).
- 전역 ignore 는 Tech Lead 판단입니다. 어느 쪽으로 정해지든 코드는 이미 양쪽 다 통과합니다.

## 7. 되돌릴 조건

이 문서가 정하는 것은 **예외의 범위**이지 규칙 자체가 아닙니다. Tech Lead 가 어느 항목이든 거부하면 그 항목의 코드를 손으로 고칩니다. 규칙을 바꾸는 것은 01의 9절 절차입니다.
