# 끝난 것

## 0. 나중에 못 바꾸는 것부터 정했습니다

나중에 바꾸면 그때까지 모은 데이터를 버려야 하는 것들을 먼저 못박았습니다.

| 무엇을 | 왜 먼저인가 |
|---|---|
| 기록 방식 | 추천하는 순간에만 존재하는 값이라 나중에 못 만든다 |
| 가입 설문 문항 | 100명 모은 뒤 바꾸면 그 답이 반쯤 버려진다 |
| 개인정보 동의 문구 | 모집 안내문에 들어가야 한다 |
| 후기 수집 방식 | 닉네임을 되돌릴 수 없게 처리한다 |
| 재료를 다 썼는지 버렸는지 구분 | 안 물어보면 나중에 물을 대상이 없다 |

> **"정했다"는 결정을 내렸다는 뜻이지, 아직 데이터가 묶였다는 뜻이 아닙니다.**
> 추천 기록·사용자 행동·실사용자·설문 응답이 **전부 0행**입니다(실측).
> 그래서 지금 고치면 공짜입니다. 진짜로 잠기는 것은 **3단계에서 기록을 켜는 순간**과
> **사용자를 모으기 시작하는 순간**입니다.

## 1. 추천 엔진이 데이터베이스를 읽게 하기

- 접속을 재사용해서, 반복 호출해도 접속 수가 늘지 않게 했습니다
- 후보 레시피 조회를 연결했습니다
- 요청 형식을 확정했습니다 — 잘못된 값은 거부됩니다
- 시험용으로 만든 가짜 레시피는 조회에서 **기본으로 건너뜁니다**

> 조회 방식을 바꿀 때는 **옛 정의를 반드시 지웁니다.** 남겨 두면 옛것과 새것이
> 둘 다 호출 가능한 상태가 되어, 어느 쪽이 돌았는지 알 수 없게 됩니다.

## 2. 추천 기록 남길 준비

추천 1건이 나갈 때 **무엇을 왜 보여줬는지**를 남깁니다. 이게 없으면 나중에
"왜 이 추천이 나왔나"에 답할 수 없고, 추천을 개선할 근거도 없습니다.

- 어디서 남긴 기록인지 구분 — 나중에 방식을 바꿔도 옛 데이터와 섞이지 않게
- 평가에 꼭 필요한 값이 빠지지 않게 함께 저장
- 기록이 실패해도 추천은 살립니다 — 대신 실패 횟수를 셉니다
- 누가 쓴 것인지 구분 — 실사용자 / 게스트 / **개발·디버깅**

> 기록 실패가 추천을 죽이면 안 됩니다. 그렇다고 조용히 넘기면 데이터가 비어가는 걸
> 아무도 모릅니다. 그래서 **넘기되 반드시 셉니다.**
>
> 개발하면서 만든 트래픽이 실사용자 지표에 섞이면, 나중에는 갈라낼 방법이 없습니다.

**아직 실제 기록은 켜지지 않았습니다.** 켜는 것은 3단계입니다.
