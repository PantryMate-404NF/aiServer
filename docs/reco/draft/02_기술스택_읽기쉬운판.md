# 기술 스택 — 무엇을 쓰고, 왜 쓰나

> 작성자: 박재우 · 작성일: 2026-09-03

우리는 **냉장고에 있는 재료로 만들 수 있는 요리**를 추천하는 시스템을 만들고 있습니다.
이 문서는 그걸 만드는 데 쓰는 도구 목록입니다. 항목마다 **왜 그걸 골랐는지**를 한 줄씩 붙였습니다.

**표시는 하나뿐입니다.**

- 표시가 없으면 — **지금 실제로 돌아가고 있는 것**
- ⬜ — **아직 안 만든 것.** 이름만 정해뒀거나 계획만 있습니다.

---

## 지금 돌아가고 있는 것

| | 상태 |
|---|---|
| 데이터베이스 (PostgreSQL) | 떠 있고, 레시피 데이터도 다 들어와 있습니다 |
| 캐시 (Redis) | 컨테이너는 떠 있지만 ⬜ 코드에서 아직 안 씁니다 |
| 재료 이름 정리 | 규칙 4단계까지 만들어져 있습니다 |
| 추천 API 서버 | 형태만 있는 가짜 서버가 돕니다 — 점수는 아직 아무 숫자나 나옵니다 |
| 화면 · 실험 기록 | ⬜ 아직 없습니다 |

## 개발 환경 만들기

언어는 Python 3.12 하나입니다. 설치는 **자기 트랙 글자를 넣어서** 한 번만 하면 됩니다.

```bash
make install TRACK=A   # A · B · C 중 자기 것
```

| TRACK | 추가로 깔리는 것 | 왜 필요한가 |
|---|---|---|
| A 데이터 | 계산 라이브러리 | 재료를 숫자로 바꾸고 비슷한 것끼리 묶으려고 |
| B 엔진 | 서버 + 계산 라이브러리 | 추천 API 를 띄우고 점수를 계산하려고 |
| C 화면·평가 | 화면 도구 + 계산 + 실험 기록 | 결과를 눈으로 보고, 실험한 것을 남기려고 |

트랙마다 필요한 도구가 달라서 **자기 것만** 깔립니다.

> ⚠️ **`uv sync` 를 맨손으로 치지 마세요.**
> 목록에 없는 프로그램을 **지워버립니다.** 실제로 이것 때문에 서버 프로그램과 계산
> 라이브러리가 사라져서 가짜 서버가 죽은 적이 있습니다.
> `make install` 은 `TRACK` 을 안 주면 아무것도 하지 않고 멈춥니다. 그게 안전장치입니다.

지금 이 컴퓨터에 깔린 것은 **B 트랙 구성**입니다. 화면 도구·실험 기록·순위 학습 모델은
안 깔려 있어서, C 트랙 일을 하려면 `make install TRACK=C` 를 먼저 해야 합니다.
안 하면 `make mlflow-ui` 가 깨집니다.

### uv 가 없는 컴퓨터라면

코랩이나 채점 서버처럼 uv 를 깔 수 없는 곳을 위해 **같은 목록의 사본**을 따로 두었습니다.

```bash
pip install -r requirements/B.txt    # base · A · B · C · all 중 자기 것
```

> ⚠️ **이 사본 파일들을 손으로 고치지 마세요.**
> 사본은 진짜 목록에서 자동으로 뽑아낸 것입니다. 손으로 고치면 진짜 목록과
> 조용히 달라지고, 달라진 걸 아무도 눈치채지 못합니다.
> 도구를 추가할 일이 생기면 `pyproject.toml` 을 고친 다음 `make requirements` 를
> 실행해서 사본을 다시 뽑으세요. 사본이 어긋났는지는 `make requirements-check` 가
> 알려줍니다.

### 아직 안 까는 것 두 가지

| 무엇 | 왜 미루나 | 언제 까나 |
|---|---|---|
| 순위 학습 모델 (lightgbm) | 학습에 쓸 사용자 기록이 아직 없습니다 | 6주차 말에 기록이 500건을 넘으면 |
| 문장 임베딩 (sentence-transformers) | 이걸 쓰는 코드가 없고, 딸려오는 파일이 2GB 입니다 | 이번 3주에는 안 씁니다 |

둘 다 필요해지면 이렇게 얹습니다:

```bash
make install TRACK=B EXTRA=rank-v1
```

> ⚠️ `EXTRA` 는 **한 번 붙이고 끝이 아닙니다.** 다음에 `make install` 을 할 때
> 빼먹으면 방금 깐 것이 도로 지워집니다. 한 번 얹었으면 계속 붙이세요.

## 데이터가 사는 곳

**PostgreSQL 16** 하나에 전부 들어 있습니다 (Docker 로 띄웁니다).
사용자·취향·레시피·후기·추천 기록까지 표 29종입니다.

데이터베이스에 얹어 쓰는 기능이 셋 있습니다.

| 무엇 | 어디에 쓰나 |
|---|---|
| 비슷한 것 찾기 (pgvector) | 맛과 재료 구성을 숫자 목록으로 저장해두고, 비슷한 레시피를 찾습니다 |
| 비슷한 글자 찾기 (pg_trgm + 한글 자모 쪼개기) | "다진마늘" 과 "마늘 다진 것" 을 이어붙일 후보로 올립니다. **자동으로 확정하지는 않고** 사람이 검수하도록 제안만 합니다 |
| 위아래 관계 저장 (ltree) | 견과류 아래 아몬드 · 호두 처럼 카테고리를 계층으로 둡니다. 알레르기 제외에 씁니다 |

들어와 있는 데이터는 만개의레시피에서 모은 것입니다.

```
레시피        46,353건
재료 원문    451,862줄
조리 순서    362,677단계
후기         624,422건
```

재료 사전은 직접 만들었습니다 — 재료 **536종** + 다른 이름 **245개** + 카테고리 **66개**
+ 알레르기 그룹 **10개**.

분석은 따로 도구를 두지 않고 **PostgreSQL 에 직접 물어봅니다.** 로그가 이미 DB 안에 있어서
밖으로 뺄 이유가 없습니다.

⬜ 영수증 사진은 직접 찍어서 50~100장 모을 예정이고, 레시피 이미지는 아직 0건입니다.

## 추천이 도는 방식

**후보 고르기 → 걸러내기 → 점수 매기기** 순서입니다.

**걸러내기 — 알레르기는 점수를 깎지 않고 아예 뺍니다.** 걸러내는 길이 네 개입니다.

1. 사용자가 직접 적은 재료
2. 그 재료가 속한 카테고리 아래 전부
3. 같은 알레르기 그룹에 속한 재료
4. 직접 적은 재료가 속한 그룹까지 확산 — 단, **등급이 '알레르기' 인 것만**

**점수 매기기 (v0)** — 항목 17개를 비중대로 더해서 순위를 냅니다.
설계상 비중의 합은 1.00 인데, 아직 데이터가 없는 항목이 있어 **실제로 도는 것은 0.94** 입니다.
⬜ 점수를 실제로 계산하는 부분은 아직 안 만들었습니다.

⬜ **v1 은 순위 학습 모델(LightGBM)** 입니다. 7주차 일입니다. 다만 조건이 붙어 있습니다 —
6주차 말까지 학습에 쓸 추천 묶음이 **500개**가 안 모이면 포기하고 v0 로 마무리합니다.

**비슷한 사람이 좋아한 것을 추천하는 방식은 접었습니다.** 레시피 한 건당 사용자 반응이
**0.091건**뿐이라 학습이 안 됩니다.

딥러닝 프레임워크로는 PyTorch 2.x 를 둡니다.

## 재료 이름 정리 — 생성모델 없이 규칙으로

재료 원문에서 실제 재료 이름을 뽑아내는 일은 **생성모델을 쓰지 않고 규칙으로** 만들었습니다.
4단계 규칙으로 재료 원문의 **80.8%** 를 사전 항목에 연결합니다.

맛 특성을 수치로 내는 것까지는 되어 있고, **수량 환산(1큰술이 몇 그램인지)은 보류**입니다.
"전부 완성됐다" 고 쓰지 마세요.

## 추천 사유 문구

"이 레시피를 왜 추천했는지" 한 문장은 **미리 계산해서 저장**합니다.
화면을 볼 때마다 생성모델을 부르지 않습니다 — 재보니 **필요한 속도의 9분의 1**밖에 안 나왔습니다
(초당 833 이 필요한데 90.9 가 한계). 그래서 실시간은 정해진 틀에 값만 끼우는 문장으로 갑니다.

저장할 자리는 만들어 뒀습니다 — `daily_recommendation.reason` 과, 그 문구가
**어디서 나왔는지**(생성모델 · 틀 · 대체) 적는 칸입니다. 나중에 어느 쪽이 나은지 비교하려면
이 구분이 있어야 합니다. ⬜ 문장을 실제로 만들어 넣는 배치는 3주 계획 밖입니다.

## 서버 · 화면 · 실험 기록

- **API 서버**: FastAPI + Uvicorn
- **입출력 형식 검사**: Pydantic — 약속한 형태와 다르면 그 자리에서 걸립니다
- **호출 순서**: 프론트 → 백엔드 → **AI**. 우리는 프론트와 직접 이야기하지 않습니다
- **화면**: Streamlit ⬜ 아직 없습니다
- **실험 기록**: MLflow — 기록은 파일이 아니라 PostgreSQL 의 `mlflowdb` 에 쌓입니다 (`make mlflow-ui`)
- **컨테이너**: Docker Compose (`infra/docker-compose.yml`)
  - 지금 떠 있는 것: `reco-postgres` · `reco-redis`
  - 정의만 되어 있고 ⬜ 아직 못 띄우는 것: `mlflow` · `grafana` · `reco-api` · `dashboard`
- **버전 관리**: Git + GitHub
- ⬜ 배포 방식과 로그 남기는 방식은 아직 정하지 않았습니다

## 조용히 틀리는 네 군데

에러가 안 나서 못 알아채는 것들입니다. 화면상으로는 전부 정상으로 보입니다.

### 1. 시간대는 `Asia/Seoul` 이어야 합니다

정본은 `01_extensions.sql` 안의 `ALTER DATABASE` 입니다.
세계 표준시로 돌면 **한국 시간 자정부터 오전 9시 사이에 날짜가 하루 전으로 계산**돼서
소비기한 임박 판정이 어긋납니다.
컨테이너 설정만 바꾸는 걸로는 부족합니다 — **밖에서 붙는 프로그램에는 그게 적용되지 않습니다.**

### 2. 알레르기는 저장할 때 등급을 '알레르기' 로 넣어야 합니다

기본값인 '피하기' 로 들어가면 **같은 그룹으로 퍼뜨리는 동작이 조용히 꺼집니다.**
아몬드만 등록한 사람에게 호두와 잣이 그대로 추천됩니다.

### 3. MLflow 를 `recodb` 에 붙이면 안 됩니다

MLflow 가 자기 표 15개를 우리 스키마 안에 쏟아붓습니다.

### 4. 백엔드가 요청 번호와 순위를 되돌려줘야 합니다

우리가 추천을 내보낼 때 준 **요청 번호와 몇 번째 자리였는지**를,
사용자가 눌렀을 때 그대로 실어서 돌려줘야 합니다.
접속 번호 앞에 붙이는 글자도 백엔드가 붙입니다 — `c-` 실사용자 · `g-` 게스트 · `d-` 개발·디버거.

빠뜨려도 에러가 안 납니다. 기록은 정상적으로 쌓입니다.
그런데 **개발하면서 만든 트래픽을 나중에 걸러낼 수 없게 됩니다.**

## 나중에 — 지금은 넣지 않습니다

| 도구 | 언제 넣나 | 지금은 무엇으로 하나 |
|---|---|---|
| DuckDB + Parquet | 로그가 수천만 행을 넘거나, 분석을 DB 밖으로 빼야 할 때 | PostgreSQL 에 직접 물어보기 |
| Polars 또는 pandas | 배치가 메모리에 안 들어가거나, 화면이 못 받는 형태를 그릴 때 | 순수 Python · SQL 집계 · numpy |
| Feast | 랭킹 모델이 2개 이상이거나 점수 항목이 50개를 넘을 때 | `features.py` 를 손으로 관리 |
| NVIDIA Triton | 모델 3개 이상을 동시에 띄울 때 | FastAPI 가 직접 불러 쓰기 |
| Apache Iceberg | 예전 데이터를 그대로 재현하거나 삭제 요청에 대응해야 할 때 | Parquet 폴더 |
| SASRec | 사용자 한 명당 반응이 10건 이상 모일 때 | 콘텐츠 기반 추천 |
| Dagster / Airflow | 배치를 시간표대로 돌려야 할 때 | Makefile |

**아직 멀었습니다.** 지금 DB 는 약 520 MB 이고, 8주치 로그가 다 쌓여도 0.7 GB 쯤입니다.

두 가지만 미리 알아두세요.

- **로그를 파일로 빼면** 두 로그를 요청 번호로 잇는 연결이 끊깁니다.
  그 연결이 학습의 전부이므로, 빼려면 그것부터 해결해야 합니다.
- **표 계산 도구를 지금 넣으면** 세 사람이 각자 다른 도구로 같은 집계를 하게 됩니다.

## ⬜ 아직 손도 안 댄 것

3주 계획 밖입니다.

- **영수증 사진 읽기** — 사진 반듯하게 펴기(OpenCV) → 글자 읽기(PaddleOCR 한국어)
  → 읽어낸 글자를 좌표로 묶어 표 모양 복원
- **생성모델** — 어떤 모델을 쓸지 미정. 출력은 정해진 형식만 받도록 강제할 예정
- **문장을 숫자로 바꾸는 모델** — `ko-sroberta` 또는 `bge-m3`
- **단어로 찾기** — BM25 · TF-IDF
