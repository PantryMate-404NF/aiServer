# 🔴 "절대 바꾸면 안 되는 것"은 무엇인가

**스키마가 아니다.** 스키마는 바꿀 수 있다 — 비용이 조율일 뿐 데이터 손실이 아니다.
진짜로 못 되돌리는 것은 따로 있고, **지금은 대부분 아직 잠기지 않았다.**

## 층 1 — 지금 바꿔도 공짜다

실측(2026-09-02): 아래가 전부 **0행**이다.

```
추천 기록      0
사용자 행동    0
실유저         0
온보딩 응답    0
```

그래서 **지금은 로그 규약도 온보딩 문항도 가중치도 자유롭게 바꿀 수 있다.**
"S0에서 동결했다"는 것은 *결정을 내렸다*는 뜻이지 아직 데이터가 묶였다는 뜻이 아니다.

| 무엇 | 비용 | 규칙 |

> **다른 두 사람의 작업 중이던 결과가 날아가서**다. 시간을 맞춰서 하면 된다.

# 🔴 백엔드와의 인터페이스 — 세 트랙 전부 영향받는다

**AI 파트는 프론트와 직접 말하지 않는다.** 백엔드가 유일한 호출자다
(기능명세 초안 `COMMON-005` "백엔드에서만 호출").

```
① BE → AI   추천 요청     user_id · 🔴 session_id(c-/g-/d-) · top_k · max_missing · max_minutes
② AI → BE   추천 20건     레시피 · 부족재료 · 이유 · 🔴 request_id · position
③ BE → AI   행동 이벤트   🔴 request_id · position 을 그대로 되돌려 실어야 한다
```

> 🔴 **③ 이 안 지켜지면 학습이 성립하지 않는다.** 백엔드가 `request_id` 를
> 빼먹어도 `/v1/events` 는 **200 을 돌려준다** — 계약상 선택 필드다.
> 🔴 **응답은 200 이지만 `rejected` 로 집계되고 그 행은 저장되지 않는다.**
> 상태코드만 보고 성공 처리하면 그 이벤트는 사라진다. 추천과 이을 수 없어
> **"3번째로 보여준 그것을 눌렀다"가 복원되지 않는다.** 클릭 기록만 남으면
> 우리가 위에 올린 것이 인기 있어서 눌린 것처럼 보이고, 그 데이터로 학습한
> 모델은 자기 편향을 재생산한다. **몇 주 뒤에야 드러난다.**

담당은 **B-16**. 다만 C 는 화면에서 이 연결이 끊긴 요청을 볼 수 있어야 하고
(고아 이벤트 비율), A 는 영향이 없다.

# 환경 준비 — 각자 자기 트랙만 깐다

`pyproject.toml` + `uv.lock` 이 정본이다 (옛 `db/requirements.txt`·`reco/requirements.txt`
2벌은 09-02 에 폐지). uv 를 못 쓰는 환경을 위해 `requirements/*.txt` 사본을 함께 둔다 —
사본은 `make requirements` 로만 만든다.

```bash
brew install uv                     # 없으면
brew install --cask orbstack        # 없으면 (Docker 대체)
./setup.sh --track A                # 자기 트랙: A 데이터 · B 엔진 · C 관측
```

`setup.sh` 가 `.venv` 생성 → 의존성 → 컨테이너 → 시드 → 검증까지 한다.
**여러 번 돌려도 안전하다** — 이미 있는 것은 건드리지 않고, 지우는 명령은
하나도 부르지 않는다. 진단만 하려면 `./setup.sh --check`.

손으로 하려면 아래와 같다(스크립트가 하는 일과 같다):

```bash
uv venv
make install TRACK=A
make bootstrap
```

| 트랙 | 추가로 깔리는 것 |
|---|---|
| **A** 데이터 | `ml` — numpy · scikit-learn |
| **B** 엔진 | `api` — fastapi · uvicorn  ＋ `ml` |
| **C** 관측 | `dash` — streamlit  ＋ `ml` ＋ `obs` — mlflow |

공통(전 트랙): pydantic · pyyaml · psycopg2-binary ／ dev: httpx2

> 🔴 **`uv sync` 를 맨손으로 치지 마세요.** 락에 없는 패키지를 **지웁니다.**
> 09-02 에 실제로 fastapi·numpy 가 사라져 mock 서버가 죽었다.
> 반드시 `make install TRACK=?` 로 하세요 — TRACK 없이 실행하면
> 아무것도 설치하지 않고 안내만 나옵니다.

> ⬜ **`lightgbm` 은 아직 안 깐다.** 랭킹 v1 용이고 W6 말 컷라인(누적 그룹 ≥ 500)을
> 통과해야 시작한다. 그때 `make install TRACK=B EXTRA=rank-v1` 로 추가한다.
> 🔴 EXTRA 는 **그때 한 번만이 아니다.** 다음번 `make install` 에서 빼먹으면
> `uv sync` 가 lightgbm 을 도로 지운다 — 얹었으면 계속 붙이세요.

> ⬜ **`sentence-transformers`(embed) 는 이번 3주에 안 깐다.** A-12 가 임베딩 없는
> TF-IDF→SVD 판으로 확정돼서 부를 코드가 없고, torch 2GB 를 끌고 온다.
> 나중에 content_emb 판으로 갈 때 `EXTRA=embed` 로 얹는다.

**uv 가 없는 환경(순정 pip · 코랩 · 채점 서버)** 이면 사본을 쓴다:

```bash
pip install -r requirements/B.txt     # base A B C all 중 자기 트랙
```

> 🔴 `requirements/*.txt` 를 **손으로 고치지 마세요.** `pyproject.toml` 을 고치고
> `make requirements` 로 다시 뽑습니다. 손으로 고치면 락과 조용히 갈라지고,
> 갈라진 걸 아무도 모릅니다. `make requirements-check` 가 그걸 잡습니다.

# 문서에 검증 건수를 적을 때

`make doc-check` 가 `docs/` 아래 모든 `.md` 를 훑어서 **문서가 적은 건수 vs 실제로
돌려본 건수**를 대조한다. 검사기가 읽을 수 있게 두 모양으로만 쓴다.

| 무엇 | 어떻게 쓰나 |
|---|---|
| **전체** 건수 | 명령이 먼저, 수가 뒤 — `` `make contract` 98건 `` · `` `make ddl-test` **47건** `` |
| **부분** 건수 (그 항목이 더한 몫) | 수가 먼저, 명령이 뒤 — `` 8건 (`make contract` 중) `` |

옛 값을 일부러 남길 때는 취소선을 치거나 화살표를 쓴다 — `~~84~~ **98**` · `65건 → 98건`.
검사기가 그건 건너뛴다.

> 🔴 09-03 에 `contract` 가 84→98, `ddl-test` 가 41→47 로 늘면서 **8개 파일 21곳이
> 한꺼번에 낡았다.** 그때 이 검사가 파일 하나만 보고 있어서 하나도 못 잡았다.
> 지금은 전부 본다 — 건수를 적었으면 `make doc-check` 를 돌리고 커밋하세요.
